# LONGVIEW — long-horizon session synthesis (ADR-005)

Turns 9 months of local agent sessions (Antigravity brain + Claude Code, via the
memo-ray entity store) into a queryable knowledge graph and cited deliverables —
a portfolio report, a PRD for what comes next, an operator skill, a book, and a
TOGAF SAD — all generated by the local model (Lemonade `qwen3.5-9b-FLM`), for
electricity instead of tokens.

Design: `runtime/architecture/ADR-005-longview-session-synthesis.md`.

## Prerequisites

- Lemonade serving on `:13305` with `qwen3.5-9b-FLM` (or set `LONGVIEW_MODEL`).
  The FLM recipe currently loads with `ctx_size 4096`, which caps evidence packs
  at 7500 chars and reduce inputs at 8500 chars (both enforced). **Raising the
  FLM ctx_size to 16384+** and setting `LONGVIEW_EVIDENCE_BUDGET=12000` /
  `LONGVIEW_REDUCE_INPUT=30000` buys noticeably higher-fidelity synthesis.
- Benny runtime on `:8005` (only needed for Phase D graph ingestion + TOGAF run).
  The workspace lives under the **runtime's resolved home** (desktop config →
  `%APPDATA%\space-agent\benny-home\benny` on this box) — `lib/config.mjs`
  resolves it with `packaging/desktop/home_resolver.js`, same as the runtime.
- memo-ray checkout as a sibling of prime-silo (or set `MEMORAY_DATA_DIR`);
  its server running is optional — sync falls back to invoking the parsers.

## Manifest mode (the managed way — use this)

The pipeline definition of record is
`runtime/manifests/templates/longview_synthesis.json` (variables + phases).
Run and manage it from the Benny CLI:

```powershell
cd prime-silo/runtime
python benny_cli.py longview run                  # all enabled phases, resume-safe
python benny_cli.py longview run --phase model    # one phase
python benny_cli.py longview run --delta          # only new/changed sessions
python benny_cli.py longview status               # live heartbeat (phase, ETA, rates)
python benny_cli.py longview report               # honest ledger report
```

(Equivalent direct form: `node scripts/longview/longview.mjs run [manifest] [--phase X] [--delta]`.)
Per ADR-005 §4 the manifest's tasks are the _phases_ — the per-session
fan-out stays inside the map phase's checkpointed loop, never as swarm tasks.
Edit the manifest to change model, budgets, batch sizes, or to disable phases.

Resume-safe at card granularity: Ctrl+C anytime, rerun the same command, it
continues where the ledger says it stopped. Delta reduce re-runs automatically
once ≥5 new cards accumulate (`delta_reduce_threshold`).

Phases are **isolated** (v1.10.1): one that throws is ledgered as a
`phase_error` entry and skipped; the rest of the run continues. A missing
deliverable always has a ledger entry saying why.

## Graph ingestion (deep synthesis)

`deep_synthesis: true` in the manifest is what turns card docs into
Document/Concept nodes in Neo4j — without it `/rag/ingest` writes **vectors
only** and the knowledge-graph views stay empty (found live: 55 cards in
Chroma, zero graph nodes). Synthesis is LLM-per-document and the runtime runs a
**full clustering pass after every batch** (~hours at ~30k concepts), so one
large batch (`ingest_batch_size: 40`) amortizes that cost to a single pass; the
phase is idempotent (old vectors per source are deleted before re-add), so
re-running `--phase model` after clearing `longview/rollups/ingested.json`
back-fills the graph. **Never run a deep ingest concurrently with reduce/opus**
— it wedges the shared Lemonade instance and the LLM phases get empty replies.

## Phases (runnable individually)

| Phase     | Command     | What                                                             | LLM? |
| --------- | ----------- | ---------------------------------------------------------------- | ---- |
| inventory | `inventory` | memo-ray sync + session census                                   | no   |
| extract   | `extract`   | deterministic evidence packs (≤9 KB each)                        | no   |
| map       | `map`       | evidence → session cards, gated + ledgered (the long part)       | yes  |
| model     | `model`     | rollups + cards into the workspace knowledge graph               | no\* |
| code      | `code`      | repo junction → Tree-Sitter code graph → `CORRELATES_WITH` links | no\* |
| weave     | `weave`     | discovery loops: questions → cited notes → re-ingested           | yes  |
| reduce    | `reduce`    | dossiers → themes → report/PRD/skill/book (+ TOGAF prep)         | yes  |
| opus      | `opus`      | _The AI Vampire_: outline → chapters → ~100 cited sections       | yes  |
| pdf       | `pdf`       | assembled book → print-styled HTML → PDF (headless Edge/Chrome)  | no   |

\* `model` calls Benny `/rag/ingest` (embeds locally; skip with `--no-graph`);
`code` shells out to `benny enrich`.

### Book on demand (decoupled from ingestion)

Opus needs no ingest — it reads THEMES/dossiers from `data_out/` and retrieves
evidence from the vectors/graph that already exist:

```powershell
node scripts/longview/longview.mjs reduce --only dossiers,themes,report  # refresh foundation
node scripts/longview/longview.mjs opus                                  # resume-safe per section
node scripts/longview/longview.mjs pdf
```

## Where things land

```
$BENNY_HOME/workspaces/longview/
├── longview/            state: inventory, evidence/, cards/, rollups/,
│                        ledger.jsonl (honesty), status.json (heartbeat)
├── data_in/             session-card markdown (graph corpus)
└── data_out/            deliverables:
    ├── PORTFOLIO-REPORT.md, THEMES.md, PRD-WHAT-COMES-NEXT.md
    ├── dossiers/<project>.md, skills/working-with-this-operator.SKILL.md
    ├── book/BOOK.md (+ outline.json, chapter-NN.md)   short-form (reduce phase)
    ├── opus/THE-AI-VAMPIRE.md|.pdf (+ sections/)      long-form (opus + pdf phases)
    ├── discovery/loopN_qM.md                          weave discovery notes
    └── TOGAF-RUN.md     the human-launched SAD swarm command (ADR-001)
```

Deliverables are proposals in `data_out/` — promoting a skill into
`~/.claude/skills`, or the PRD into the roadmap, stays a human step.

## Observability

- `status.json` — updated after every card; Bridge's file browser can watch it.
- `ledger.jsonl` — append-only; `report` reads only this. Numbers not in the
  ledger don't get claimed (memo-ray token-audit lesson).
- Phase D ingestion and the TOGAF swarm run in the Benny runtime ⇒ visible in
  Mission Control / the activity feed like any other run.
- Lemonade's own console shows live generation.

## Honest limitations (v1)

- 63 of 130 indexed sessions are "thin" (empty brain dirs; conversations exist
  only as unparsed protobuf). They are ledgered `skipped_thin`, not guessed at.
  A `.pb` decoder or the `antigravity-backup/` dirs would raise coverage.
- Claude coverage in the memo-ray store is 7 sessions vs 36 transcript files on
  disk — worth a look at `claudeParser` thresholds.
- Card quality has a 9B ceiling; every claim carries session-id citations so
  weak cards are visible and re-runnable (`map --force` after deleting a card).
