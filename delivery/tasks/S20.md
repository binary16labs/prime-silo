# S20 — what is on this backup drive that is not already on F:

## Goal

The owner plugs a backup drive into the T480, opens the Estate Map, and sees what on that drive has
no copy on F: — so they know what to copy before retiring the drive. Report only: nothing is moved.

## Context pointers (never inline content)

- `delivery/board/LOG.md` — the 2026-10-03 reset: the owner judged EP-S overcomplicated
- `server/coordination/lib/estate_map_files.mjs` — the Everything adapter (path and size per file)
- `server/coordination/lib/estate_map_producer.mjs` — the roots a machine offers; single flight

## TDD plan

1. Compare two roots on this machine: list both with sizes; a file whose size matches nothing on
   the target is "only on the drive" without being read. On a size match, a partial hash (first and
   last 4 MB plus size), then a full hash on a partial match. Only a FULL hash match is "on F:".
2. A partial match whose full hash was not finished is "unconfirmed", never "on F:".
3. Paths a quarantine rule matches are counted, never listed. Names never leave this machine.
4. POST /api/estate/compare (loopback only, offered roots only, one at a time) and GET for progress
   and the latest result, kept per drive pair with the time it was taken.
5. Panel: a Backups tab — pick a drive, compare with F:, watch progress, see totals and the largest
   folders of drive-only files, download the drive-only list as CSV. Also: "withheld by this node's
   privacy rules" becomes the true reason (no folder is named for listing), and a Sweep-all button,
   because a single-drive sweep replaced the machine's totals with that drive's alone.

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: a backup drive against F:
  Scenario: a file F: already holds is not reported
    Given the same bytes on the drive and on F:, under different names
    When the drive is compared with F:
    Then it is "on F:", confirmed by full hash

  Scenario: same size, different bytes is not a copy
    Given a file on the drive and one on F: of equal size and different content
    When the drive is compared with F:
    Then the drive's file is "only on the drive"

  Scenario: a private file is counted, not listed
    Given a drive-only file whose path a quarantine rule matches
    When the comparison finishes
    Then it is in the totals and absent from every list and the CSV
```

## Out of scope

Copying or deleting anything (S7). Other machines' drives. Scheduling.

## Handoff

One gate run and one independent check (the owner's 2026-10-03 bar for read-only views): the
verifier compares two small real folders offered as roots and confirms the three Scenarios.
