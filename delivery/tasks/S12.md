# S12 — the column width is winget's rule, not ours

## Goal

`charWidth` stops being a hand-written guess at which characters are wide and becomes the rule
winget actually applies: **East Asian Width W or F is two columns, everything else is one, counted
per code point.**

S11 closed the CJK case and, doing so, **regressed a narrower one**: claude-s11-verifier measured
winget's real padding and found U+1F642 is padded as two columns (emoji presentation characters have
been EAW Wide since Unicode 9), while S11's `charWidth` returns 1 — so an application name
containing an emoji now throws `WINGET_MALFORMED` on S11 where it parsed on main. The same applies
to VS16, ZWJ, skin-tone modifiers, bare format marks and combining marks, which S11 counts as zero
and winget counts as one. It is loud rather than silent, and the net of S11 is still a large
improvement, but it is the exact shape S11 existed to close, reintroduced for a smaller class.

The verifier also named why the author's tests did not catch it (finding N2), and that is the real
defect to fix: **the emoji fixture was padded with the library's own `displayWidth`, and the
assertion `displayWidth("🙂") === 1` was labelled "the widths winget actually uses".** A test that
pads with the code under test is self-consistent and blind by construction. It asserted a falsehood
as fact and would have agreed with any table at all.

## The class, not the instance

A hand-maintained list of ranges drifts from the standard silently and is only ever corrected one
missing block at a time — S11 shipped one, the verifier immediately found three more gaps (Hangul
Jamo Extended-A/B, wide astral blocks below U+20000, Tangut). The choke point is to stop hand-
listing: derive the table from the Unicode East Asian Width property, record in the file which
Unicode version it was generated from, and make the tests measure against **captured real `winget`
output** rather than against our own padding.
