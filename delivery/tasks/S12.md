# S12 — the column width is winget's rule, not ours

> **Corrected 2026-09-21.** The Goal below first said East Asian Width "counted per code point", and
> asked for a variation selector, a ZWJ and a combining mark to measure one column each. That is not
> winget's rule; code written to it refuses real application names. Both verifiers read
> `winget-cli`'s own source. The text is fixed in place rather than annotated, so a future agent
> cannot restore the bug from it.

## Goal

`charWidth` stops being a hand-written guess and becomes the rule winget actually applies, which
`UTF8ColumnWidth` in `AppInstallerSharedLib/AppInstallerStrings.cpp` defines and `TableOutput.h`
pads the table with:

> **the width of a name is the sum over its GRAPHEME CLUSTERS, NFC-normalised, of 2 when that
> cluster's first code point is East Asian Width W or F, and 1 otherwise.**

So a combining mark joins its base (one cluster, one column), a ZWJ emoji sequence is one cluster of
two columns, and an Indic syllable is one cluster of one column.

S11 closed the CJK case with a hand-written range list and, doing so, regressed a narrower one:
U+1F642 has been EAW Wide since Unicode 9, so an emoji in a name threw `WINGET_MALFORMED` where it
had parsed. S11's tests could not catch it, because the fixture was padded with the library's own
`displayWidth` and then `displayWidth` was asserted against it — self-consistent and blind by
construction.

## The class, not the instance

A hand-maintained range list drifts from the standard silently and is only ever corrected one block
at a time. The choke point is to stop hand-listing: generate the table from the Unicode East Asian
Width property, record which Unicode version it came from, and measure the tests against **captured
real `winget` output** rather than against our own padding.

## Handoff

Verifier re-derives winget's rule from primary evidence rather than from this contract, confirms the

## Verified

Both verifiers diffed the generated table against their own fetch of `EastAsianWidth.txt` 17.0.0:
182,876 wide code points on each side, **0 differing of 1,114,112**. The table was never the defect;
the unit was. claude-s12-verifier-2 also proved exhaustively that NFC never changes a cluster's
first-code-point W|F class, so the per-cluster `normalize("NFC")` is redundant and is kept only
because winget does it (~10 ms per 225-row parse, noise inside an 11.9 s sweep).
