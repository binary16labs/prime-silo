# U6 — what is only outside F:, from the catalogues alone

**Stage 2 of `delivery/PLAN-consolidate-first.md`, signed by the owner 2026-11-15** ("Signed so
nodes align to one drive and one node is assigned to taking a backup to F, this case the T480").
F: is the one consolidation drive; the T480 is its only writer. Band M, 500 lines.

## Goal

One answer for the owner and for U7: **what content exists somewhere on the T480's catalogued
sources and not on F:**, per source, kind and bytes. It is answered from the catalogues, never by
reading a disk: every source and F: are already fingerprinted by U1/S21.

## Design

1. **Sole content = a sha256 on a source catalogue that F:'s catalogue does not hold.** Matched by
   content, not path: a file renamed or moved on F: is still "on F:". Empty files are ignored.
2. **Per source, never mixed:** each offered root and each catalogued backup drive (attached or not:
   the catalogue answers for a drive that is away, dated) gets its own line: files, bytes and kinds
   only outside F:; files already on F:; and **cannot tell** for rows with no fingerprint (OneDrive's
   cloud-only files, `online_only`), counted by files and bytes and never called "on F:".
3. **A source's own duplicates count once**: two copies of one photo on a backup drive is one item
   to copy, and the bytes to copy are said that way ("1,200 files, 34 GB to copy; 9 GB of that is
   repeats inside the source").
4. **Freshness is said**: each line names the age of the source's catalogue and of F:'s. A source
   catalogued before F:'s last pass is still compared, with both dates shown.
5. **Answered off the hub's thread** (the summary-worker pattern, S21/S30): a worker writes the result
   beside the catalogues; the Library tab reads it. A CSV per source lists the sole files locally;
   counts only on the panel.
6. **Private stays private**: a quarantined path is counted, never named, in the CSV and the panel.
