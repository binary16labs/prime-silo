# R2 — TOGAF SAD generation with deterministic diagrams

## Goal
A target-parameterized workflow type (evolving the existing togaf_sad_* templates, fixed 6-task
shape) producing a TOGAF-structured SAD: Vision, Business/Application/Data/Technology sections
from R1 dossiers, interface catalog, constraints & risks, gaps, and a compliance appendix mapping
sections to ADM artifacts. Diagrams are GENERATED from graph queries (Mermaid/Graphviz → SVG) —
the model selects and captions, never invents boxes.

## Context pointers
- Plan §8 R2 card (PLAN-local-power-unified-ui.md:423-428); the 6-task-template lesson: sections fixed, target is the parameter (never planner growth)
- Outputs: SAD markdown → existing PDF path + diagram SVGs + machine-readable sad.json (sections, claims, citations) for R3
- Optional flagged: VIS-001 vision judge scores diagram legibility, advisory only

## TDD plan
1. Red: fixture SAD contains every required TOGAF section (checklist assertion).
2. Red: interface catalog set-equals the graph's endpoint set (both directions).
3. Implement type + diagram generators — green. 4. 100% citation resolution; every diagram source compiles; G3 catalog registration dry-runs green.

## Acceptance
```gherkin
Feature: an architecture document that cannot lie
  Scenario: structurally complete
    Given the fixture SAD
    Then every required TOGAF section is present per the checklist

  Scenario: no invented endpoints
    Then the interface catalog is set-equal to the graph's endpoints in both directions

  Scenario: diagrams are facts
    Then every diagram source compiles and every referenced node exists in the graph
    And 100 percent of claims cite resolvable node ids
```

## Out of scope
Modularization (R3), scaffolding generation (explicit non-goal), new TOGAF sections.

## Handoff
Verifier re-runs r2.py. Registered as a G3 catalog type; sad.json schema documented.
