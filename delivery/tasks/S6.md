# S6 — storage policy and the centralisation planner

## Goal

A declarative `coordination/estate/storage-policy.yaml` says where each category belongs (e.g. models -> nas:models),
minimum device coverage, and what never leaves its machine. A pure planner diffs the folded map and integrity
results against the policy and raises proposals through the existing governance ledger, never executing. Each
proposal carries bytes, file count, and sole-copy warnings.

## Context pointers (never inline content)

- `architecture/SOLUTION-estate-map.md` §4.2
- `server/coordination/lib/estate_govern.mjs`, `governance.mjs` (proposal_raised; frontier authorship asks, takes nothing)
- R31 quarantine rules (never proposed for movement)

## TDD plan

1. Policy schema validation: unknown category or destination fails loudly with the offending key.
2. Planner output is deterministic for the same map + policy (stable ordering, stable proposal ids by content).
3. A quarantined path or a "stays local" category is never included in any proposal.
4. Re-running the planner after nothing changed raises no duplicate proposals.

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: centralisation planning
  Scenario: models on a laptop become one proposal to the NAS
    Given optimus holds 38 GB under models and the policy homes models on nas:models
    When the planner runs
    Then one proposal is raised for 38 GB with the sole-copy files listed

  Scenario: private data is never proposed
    Given a quarantined document under optimus Documents
    When the planner runs
    Then no proposal references that path or its hash

  Scenario: planning is idempotent
    Given the planner already raised a proposal for this delta
    When it runs again with an unchanged map
    Then no new proposal is raised
```

## Out of scope

Executing proposals (S7); the UI Plan tab beyond listing proposals via the existing Gov arc.

## Handoff

Verifier runs the gate and reviews the first real proposals against the map before any are signed.
