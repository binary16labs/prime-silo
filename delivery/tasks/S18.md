# S18 — the owner names which folders the map may list

## Goal

A sweep lists by name only the files under folders the owner has named, and the panel says which
folders those are. Today none can be named, so every sweep counts files by category and lists
none, which leaves integrity nothing to compare.

## Context pointers (never inline content)

- `server/coordination/lib/estate_map.mjs` — runSweep's `publicRoots` (S0's structural privacy)
- `server/coordination/lib/estate_map_producer.mjs` — `createSweeper`, which S17 left passing none
- `coordination/estate/quarantine.json` — the owner's policy file this one sits beside

## What is wrong now

S0 lists a file by name only under a public root, by design. S17's producer passes no public roots,
so every sweep's files table is empty, and S19 would have nothing to hash. The owner has no way to
name a folder short of editing code.

## TDD plan

1. Read named folders from `coordination/estate/public-roots.json` (`{ "roots": [...] }`), the
   owner's file beside the policy. Absent or malformed means none, and the panel says so — never a
   guessed default.
2. The hub's sweeps and the agent's `--sweep` pass them to runSweep. A named folder a quarantine
   rule matches is refused, as runSweep already refuses it, and the refusal reaches the panel.
3. The Sweep section says which folders are named, or that none are and every file is counted by
   category only.

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: the owner chooses what is listed by name
  Scenario: a named folder's files are listed
    Given public-roots.json naming one folder under a swept volume
    When the volume is swept
    Then files under that folder are in the node's index by name, and files outside it are not

  Scenario: no file name the owner did not choose
    Given no public-roots.json
    When a volume is swept
    Then the node's index lists no file by name, and the panel says no folder is named

  Scenario: a named folder the policy forbids is refused where the owner looks
    Given a named folder that a quarantine rule matches
    When a sweep is pressed
    Then it does not reach the map, and the panel says why
```

## Out of scope

Editing either policy file from the panel (the owner writes both, for now); anything that crosses
the wire (S19).

## Handoff

Verifier sweeps one small configured root with and without public-roots.json and compares the
node index's files table; S18's booted scenarios run inside the s3 gate's worlds, as S17's do.
