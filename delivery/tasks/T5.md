# T5 — DPO on the SFT model: preference-tune voice + tool choice

## Goal

Take the T3 SFT adapter and preference-tune it (DPO) so the model _prefers_ house-style
responses and correct tool calls over its own plausible-but-wrong alternatives. SFT teaches
what right looks like; DPO teaches right-over-wrong. Rejected samples are the model's OWN
generations that miss the reference — no human labeling, no synthetic prose enters "chosen".

## Context pointers (never inline content)

- Policy init: the T3 SFT adapter (`scripts/train/qlora/out/adapter`); base per T3 rubric
- Preference pairs built deterministically from the T2 train split (NEVER the eval split):
  chosen = the real house reference; rejected = the SFT model's greedy generation for the
  same prompt when it mismatches (Stream B: wrong tool name/args; Stream A: divergent text)
- The eval-harness greedy pass (`scripts/train/eval/run_eval.py`) already produces exactly
  these generations — extend it to dump (prompt, generated) for pair building
- Trainer: `trl DPOTrainer` (0.23.1 proven importable in the venv WITH the torchao stub
  loaded first); pre-tokenize via the shared `scripts/train/qlora/format.py` — never let
  DPO's chat rendering drift from the T3 instrument (same lesson as SFT)
- Windows gotchas + environment: `.claude/skills/house-trainer` (vcvars, cmd //c, D: staging)
- Same frozen instrument as T3: held-out NLL + tool-name match, RAG disabled

## Acceptance (BDD)

```gherkin
Feature: preference-tuned model beats its SFT parent, honestly
  Scenario: preference pairs are self-generated hard negatives
    Given the SFT model's greedy generations on train-split prompts
    When a generation mismatches the house reference
    Then a (prompt, chosen=reference, rejected=generation) pair is emitted and leak-gated

  Scenario: DPO beats SFT on the frozen instrument
    Given SFT and DPO adapters scored on the identical held-out split with RAG disabled
    When the eval report is generated
    Then DPO aggregate >= SFT aggregate and the delta per category is recorded

  Scenario: the DPO adapter merges to a loadable GGUF
    Given the DPO-trained adapter
    When merged and exported
    Then the GGUF loads in the target runtime
```
