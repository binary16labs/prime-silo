# L13 — Promotion decision function + additive eval growth

## Goal
"N+1 ≥ N" is an explicit dominance/decision rule over the metric vector (eval NLL, agent pass-rate,
cost, latency), specifying the outcome when metrics trade off (Pareto case) so "better" is decided by
rule, not relitigated per turn. And the held-out instrument grows additively — new slices added without
invalidating the historical cross-turn series. Extends R23/R30/R37 and R24. R44, R45.

## Context pointers (never inline content)
- Design: architecture/SOLUTION-longview-self-learning.md §4.6 (R44/R45) + §5.5 (decision_vector, slice added_in_turn)
- Metric vector comes from L5 executions.jsonl (eval_nll, agent_pass, cost, latency); eval anchor is the honest one
- Slice tagging: each held-out slice carries added_in_turn; cross-turn comparison uses only slices present in both turns
- Requirements R44, R45

## TDD plan
1. Dominance test red: a candidate better on all metrics returns "promote"; worse on all returns "reject".
2. Pareto test: a candidate trading eval-gain for cost-loss resolves by the stated rule (eval-anchored), deterministically.
3. Additive-eval test: adding a new slice with a later added_in_turn does not change any historical turn's series.
4. Comparability test: two turns are compared only on slices present in both (new slices extend, never invalidate).

## Acceptance (BDD — every Scenario must map to an automated test)
```gherkin
Feature: "better" is a rule, and the eval set grows without breaking history
  Scenario: strict dominance decides
    Given a candidate better on every metric
    When the decision rule runs

  Scenario: a Pareto trade-off resolves by rule
    Given a candidate that gains eval but loses on cost
    When the decision rule runs
    Then it resolves deterministically by the stated eval-anchored rule, not per-turn relitigation
  Scenario: a new eval slice does not rewrite history
    Given a new held-out slice tagged with the current turn
    When the cross-turn series is recomputed
    Then earlier turns' scores are unchanged and comparisons use only slices shared by both turns
```
