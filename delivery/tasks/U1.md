# U1 — catalogue the owner's data on every machine, Downloads first

## Goal

On any machine running Prime-Silo, the owner opens the Library tab and sees what there is to
catalogue: **their own data**, in the order the owner asked for:
1. Downloads first;
2. then OneDrive (which on the T480 holds the redirected Documents, Desktop and Pictures);
3. then Music and Videos where they live, and any profile folder the owner added;
4. then the machine's data drives (F:, backup drives) whole.

One press, **Catalogue my data**, catalogues them all in that order with the S21–S23 librarian
(Everything's listing and levelled fingerprints). Each item can also be catalogued or stopped on its
own. The Compare tab can then answer the first question the owner cares about: **what in Downloads
is not already on F:**. The operating system's overhead is never read: not Windows, Program Files,
ProgramData or AppData (owner direction, 2026-10-11). It is catalogued where the disk is: this
machine's own data, on this machine. Other machines run the same code on their own data, and the
hub learns about them only through the replicated ledger (U2–U4).

## Why (measured on the T480, 2026-10-11, Everything index)

- C: holds 2,261,759 files and 494 GB, of which about 184 GB is OS and application overhead.
- The owner's known folders are **5,719 files and 136 GB**: Pictures 79.2 GB and Documents 16.4 GB
  (both redirected into OneDrive), Downloads 40.1 GB (779 files) on C:.
- The rest of OneDrive is 1,030,301 files and 55 GB, mostly code repos, which S23's rebuildable rule
  keeps out of reading.
- The round-1 S21 verifier compared a C: folder of exactly Downloads' size (779 files, 40.1 GB)
  with F: and found 5 files already there. Downloads is very likely almost all unique to C:.

## Design

1. **What is offered comes from the registry, in the owner's order.** The Library and Compare tabs
   list the offered roots from U0:
   - **user roots**, by role: Downloads, then OneDrive, then Music, Videos and added folders;
   - then **data drives**.
   The system drive itself, `C:\Windows`, Program Files, ProgramData and AppData are never offered,
   and the routes refuse them (400) if asked directly.
2. **Roots never overlap.** A known folder inside OneDrive (Documents, Desktop and Pictures on the
   T480) is not a separate catalogue: it is catalogued once as part of the OneDrive root, and shown
   under it as a section. A known folder outside OneDrive (Downloads, Music, Videos here) is its own
   root. An added folder inside an existing root is refused, with the root it is already inside. A
   test proves no file is in two catalogues of the same machine.
3. **Catalogue my data** is a queue of the offered roots in the order of point 1.
   - It runs one root at a time through the hub's single-flight librarian.
   - Progress shows per root, with what is still queued.
   - Stop stops the current pass (S21 keeps what was committed) and clears the queue.
   - A root that fails (drive went away, unreadable) is recorded with why, and the queue moves on.
   - The queue lives in memory. After a hub restart the owner presses it again, and every pass
     resumes from what it committed (S21).
4. **Where catalogues live.** Catalogues of user roots and internal drives live in
   `BENNY_HOME/estate/library`: they describe the machine's own disk, which never leaves it.
   Catalogues of removable data drives live in `ESTATE_STORE/library` when it is set (the T480's
   F:, as signed in S21), otherwise in `BENNY_HOME` (the ASUS). Each lookup checks both, so no
   catalogue is orphaned by the rule (owner question 1).
5. **OneDrive files that are not on this disk are never read.** S23's online-only scope applies:
   such files are catalogued from Everything's listing (name, size, date), never opened, so they are
   never downloaded. The Library line says how many online-only files a root holds.
6. **Compare from user roots.** The Compare tab (S20's Backups tab, renamed) accepts user roots as
   "from", so "Compare Downloads with F:" is one press. S20's overlap refusal and S23's "read each
   F: file at most once" still apply. The result reads "In Downloads, not on F:: N files, X GB",
   with its folders and the CSV.
7. **Every machine, same code.**
   - **Windows (the T480, the ASUS):** user roots from U0, Everything's listing, falling back to the
     walk when Everything is not running in the session.
   - **Linux (the Pi, if its node runs):** the user root is `$HOME` plus mounted data drives, listed
     by the walk. Identity is the filesystem UUID (U0).
   - Each machine catalogues only what is attached to it, from its own Library tab. Nothing is
     catalogued across the network (SOLUTION-consolidation invariant 1).

## Pre-registered criteria (real T480, verifier, reported either way)

- Downloads (779 files, 40.1 GB on 2026-10-11) is catalogued first, in ≤ 10 min.
- The Downloads-to-F: comparison produces its report. The counts are reported, never names.
- With all of the T480's user roots catalogued:
  - 0 catalogue rows under `C:\Windows`, Program Files, ProgramData or AppData;
  - 0 files read there (hash-call spy over the real run);
  - 0 online-only OneDrive files hydrated (their attributes before and after are compared).
- The ASUS: its user roots are catalogued from its own Library tab, run by the owner (Everything
  needs the owner's desktop session). If not run, NOT MEASURED, never passed.

## Owner questions (answer when signing)

1. **Where catalogues live.** Recommendation: user roots and internal drives in `BENNY_HOME` on the
   machine itself; removable data drives in `ESTATE_STORE` on the T480 (as signed in S21). Downloads'
   catalogue should not vanish when F: is unplugged.
2. **The other profile folders** on the T480 (425,465 files, 119 GB: tools, models, worktrees) stay
   uncatalogued unless you add one. Is there any you want added from the start? Recommendation:
   none until you see the first results.
3. **The ASUS run.** It needs you at the ASUS (or in a remote desktop session on it) to press
   Catalogue my data, because Everything only answers inside your login session. Confirm you will
   do that after merge, or accept the slower walk run over SSH.

## Out of scope

- Fingerprints or catalogue summaries leaving a machine (U2–U4); a main-node button that
  catalogues another machine (a request event received at sync, U2–U3).
- Copies, sole copies and coverage across catalogues (U5, U6).
- Cataloguing OS or application folders, ever.

## Handoff

One gate run and one independent check by a non-author verifier on the real T480. The verifier:
- presses Catalogue my data through the API;
- confirms Downloads went first and nothing under the OS folders was listed or read;
- confirms OneDrive online-only files stayed online-only;
- runs the Downloads-to-F: comparison;
- reports the ASUS as measured (the owner ran it) or NOT MEASURED.

Counts only, never names.
