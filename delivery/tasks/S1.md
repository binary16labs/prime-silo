# S1 — file collectors: MFT-fast adapters, walker fallback, and a benchmark that decides

## Goal

The files collector maps a volume through Everything (`es.exe` over its USN-journal index), a WizTree CSV
snapshot, or the Node walker, chosen per volume, with a benchmark measuring every available adapter on the same
volumes. **Human-signed** because Everything means installing a service that reads the MFT on every node: the
owner signs the install before the adapter is enabled anywhere.

**Amended 2026-09-14 (owner decision "Raise budget, fix all", after three verifier FAILs; owner directive
"integrity is most important"; budget 500 -> 650):**

- A map is never silently incomplete. The walker counts unreadable directories, files it cannot stat and
  reparse directories it cannot identify; any count above zero fails the collector with `WALK_INCOMPLETE`, so
  S0 keeps the volume's last complete listing. A "partial" status in S0 is later work, not S1.
- Links are pointers, not files: symlinks, junctions and app execution aliases (anything `readlink` resolves)
  are excluded by every adapter. Non-link reparse files (deduplicated, cloud) are listed.
- A reparse directory is walked only when its tag identifies it as a cloud-files folder (OneDrive); a volume
  mount point is never walked (that volume is mapped as its own volume), on drive letters, UNC shares and subst
  drives alike. An unidentified reparse directory counts toward `WALK_INCOMPLETE`.
- Journal replay never loses or invents changes: moves into the volume count, a malformed stored position is
  refused, a position older than retained or from another journal is refused (`ES_JOURNAL_GAP` /
  `ES_JOURNAL_RESET`).
- WizTree's CSV has whole-second local times, so its rows cannot equal the others. It stays benchmarkable but
  is no longer selected automatically (selection: Everything, else walker), until a precise export is proven.

**Amended 2026-09-20 (owner decisions, after claude-s1-verifier-4 FAIL D16):**

- An entry the node may not read (`readlink` EACCES/EPERM, and Everything cannot report its tag either) is
  never listed as a file and never passed over: it fails the volume with `ES_INCOMPLETE` /
  `WIZTREE_INCOMPLETE` plus a count, as the walker already fails with `WALK_INCOMPLETE`.
- Because that made t480 C: permanently incomplete (66 such entries: app execution aliases in the Store's
  stale `WindowsApps.tmp`, and Docker sockets recreated whenever Docker runs), those OS-object folders are
  excluded by name beside `Windows\` and `$Recycle.Bin`: `AppData/Local/Microsoft/WindowsApps.tmp`,
  `AppData/Local/Docker/run`, `AppData/Local/docker-secrets-engine`. Any other unreadable entry still fails
  the volume. New exclusions are a contract change, never a silent code change.

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: fast file mapping
  Scenario: every adapter produces the same rows for the same tree
    Given an Everything CSV, a WizTree CSV and a walked fixture of one tree
    When each is parsed
    Then the three row sets are equal after exclusions

  Scenario: no MFT tool installed still maps the volume
    Given a machine without es.exe or WizTree
    When the files collector runs on a volume
    Then it uses the walker and records adapter "walker"

  Scenario: the benchmark reports a losing adapter honestly
    Given an adapter slower than the walker on a fixture volume
    When the benchmark runs
    Then the report shows both times and does not select the slower adapter

  Scenario: a partial walk never replaces a complete map (amendment 2026-09-14)
    Given a volume with a directory the walker cannot read
    When the files collector runs
    Then the collector fails with WALK_INCOMPLETE and the previous listing is kept
```
