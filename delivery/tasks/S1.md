# S1 — file collectors: MFT-fast adapters, walker fallback, and a benchmark that decides

## Goal

The files collector maps a volume through Everything (`es.exe` over its USN-journal index), a WizTree CSV
snapshot, or the Node walker, chosen per volume, with a benchmark measuring every available adapter on the same
volumes. **Human-signed** because Everything means installing a service that reads the MFT on every node: the
owner signs the install before the adapter is enabled anywhere.

## Context pointers (never inline content)

- `architecture/SOLUTION-estate-map.md` §2 (adapters, tiered hashing), §7 (map speed, completeness)
- `server/coordination/lib/inventory.mjs` walk (the fallback and the baseline)
- S0 collector interface

## TDD plan

1. Parse fixtures of `es.exe -csv` and a WizTree export into the same rows (path, size, mtime, isDir).
2. Selection: NTFS + Everything reachable -> everything; NTFS + WizTree present -> wiztree; else walker. The
   chosen adapter is recorded on the volume row.
2b. Owner decision 2026-09-13: use Everything 1.5 beta for its index JOURNAL (installed on t480, proven: create,
    rename with new name, delete, each with journal id + change id via `es -after-journal-pos`). First sweep is a full
    `-export-csv`; later sweeps replay the journal from the stored position. 1.4 has no journal over IPC.
2a. Owner suggestion 2026-09-13: prefer a PORTABLE Everything + `es.exe` shipped in the Prime-Silo runtime over a
    per-node install; `es.exe` talks to any running instance, but MFT access still needs the service or elevation,
    so the service is registered once (S8 broker). Confirm voidtools redistribution terms before bundling.
3. Excludes (`Windows\`, `$Recycle.Bin`, `pagefile.sys`, `System Volume Information`) identical for all adapters.
4. `estate_map_bench.mjs` times each available adapter per volume and writes counts and times, answering plan §7
   with numbers, failures included.

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: fast file mapping
  Scenario: every adapter produces the same rows for the same tree
    Given an Everything CSV, a WizTree CSV and a walked fixture of one tree
    When each is parsed
    Then the three row sets are equal after exclusions

  Scenario: no MFT tool installed still maps the volume
    Given a machine without es.exe or WizTree
    When the files collector runs on a volume
    Then it uses the walker and records adapter "walker"

  Scenario: the benchmark reports a losing adapter honestly
    Given an adapter slower than the walker on a fixture volume
    When the benchmark runs
    Then the report shows both times and does not select the slower adapter
```
