# A2 — Dev-task manifest pack (5 offloadable dev tasks)

## Goal

Five dev tasks the local model runs as pypes DAG manifests: `commit_summary`, `docstring_gen`,
`unit_test_gen`, `log_triage`, `code_review_notes`. Deterministic pre-checks first, judge second,
human-visible diff artifact always written to `agent_sandbox/drafts/offload/<run_id>/`.

## Context pointers

- Plan §2 A2 card (PLAN-local-power-unified-ui.md:149-158): task-by-task acceptance rules
- Each manifest = explicit pypes DAG (inputs/outputs per step); loops max 2 then `review_required: true`
- A1 windowing for per-function/per-file tasks; capability profiles, never model ids (§1.6)

## TDD plan

1. Per task: golden-input fixture red → handler green (order: commit_summary → docstring_gen →
   unit_test_gen → log_triage → code_review_notes).
2. docstring_gen guard: `ast.parse` passes + diff touches only docstrings.
3. unit_test_gen: generated tests execute (no import errors); failing ones marked `xfail-candidate`, never deleted.
4. Pack gate a2.py runs all five against the real endpoint.

## Acceptance

```gherkin
Feature: the local model does real dev work with checked results
  Scenario: every task passes its golden-input run
    Given each of the five manifests and its golden input
    When run against the real qwen3.5 endpoint
    Then output is schema-valid and acceptance checks pass with a judge verdict recorded

  Scenario: log triage findings are grounded
    Given a log chunk fixture
    Then every finding cites a line number that exists in the input

  Scenario: honest degradation
    Given a task whose generate-check loop fails twice
    Then the artifact is emitted best-effort with review_required true, never dropped
```

## Out of scope

Knowledge tasks (A3), MCP front door (A4), offline network audit (A5).

## Handoff

Verifier re-runs a2.py (honest `service_down` if lemonade unreachable). Docs: task catalog table in manifests/offload/dev/README.
