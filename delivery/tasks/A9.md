# A9 — Server-side call-deadline audit (no await without a deadline)

## Goal
The deep-synthesis ingest path can hang FOREVER server-side: on 2026-07-06 (13:0x) a synthesis
task froze at file 21/40 with zero lemonade traffic and zero retry log entries for >30 min — the
executor's BENNY_LLM_TIMEOUT=900s never fired, so the hang lives in a call WITHOUT a deadline
(embedding call, chroma upsert, or a post-synthesis step). Audit every await in the ingest path
and give each a deadline + honest failure.

## Context pointers
- Incident: task_registry SYNTHESIZING (20/40) longview_card_26988215.md, updated_at frozen
  12:39:24; chroma last write 12:42:53; lemonade idle from 12:42:18; flm.exe alive (no respawn)
- Executor timeout exists: runtime/benny/core/local_executor.py:133-150 (BENNY_LLM_TIMEOUT=900)
  — the hang is NOT there
- Suspects: benny/synthesis/engine.py embeddings call (~line 1126 client_obj.embeddings.create —
  check timeout), chroma upsert paths in tools/knowledge.py, clustering/correlation steps
- Client-side protection already shipped: stall detection + phase-stop (A8/A8.2, v1.12.5) —
  this task fixes the SERVER so tasks fail instead of freezing
- A0 watchdog semantics apply: busy compute may extend a deadline; idle compute + silence = fail

## TDD plan
1. Inventory: grep every await in the ingest call chain; list which have deadlines (audit doc in test docstring).
2. Failing test per gap: mock a never-resolving embedding/upsert call -> assert the task FAILS
   within its deadline and task_registry gets an honest failure entry (never frozen SYNTHESIZING).
3. Implement asyncio.wait_for/httpx timeouts per call; task status transitions to failed with the
   step name; ledger/AER entry written.

## Acceptance
```gherkin
Feature: a server synthesis task can fail, but can never freeze
  Scenario: embedding call without response fails the task in bounded time
    Given an embedding provider that never responds
    When a deep-synthesis ingest processes a document
    Then the task transitions to failed within the configured deadline
    And the task record names the step and elapsed time

  Scenario: no await in the ingest path lacks a deadline
    Given the audited call inventory in the test module
    Then every awaited external call (LLM, embedding, chroma, graph) carries an explicit timeout

  Scenario: a frozen task is impossible to reproduce
    Given the 2026-07-06 reproduction (mocked hung call at file N of a batch)
    When the batch runs
    Then the task record updated_at keeps advancing until a terminal state — never frozen mid-file
```
