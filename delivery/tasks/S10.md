# S10 — an exclusion hides only what it was written for

## Goal

The three OS-object exclusions the owner contracted for S1 (2026-09-20) stop matching their folder names
anywhere on any volume and match only inside a user profile, and the one remaining way an unreadable entry
can still be listed as a file — a row exported with an empty size — is closed. Added after
claude-s1-verifier-5's PASS, which found both (F1, F2) and a gate that fails on correct code when another
process is running (F3). All three are integrity faults under the owner directive: F1 hides a real file in
silence, F2 lists an entry nobody could identify, F3 makes a green gate mean less than it should.

## TDD plan

1. F1: a readable file at `<volume>/AppData/Local/Docker/run/compose.yaml`, and the same under a backed-up
   profile that is not a real profile root, is LISTED; the same path inside a user profile
   (`Users/<name>/AppData/Local/...`) stays excluded. A volume whose own path ends in the excluded segments
   is not excluded wholesale.
2. F2: an export row with an empty size and the reparse attribute is judged like a size-0 row — link
   excluded, unreadable entry fails the volume with its count, ordinary row listed.
3. F3: the gate's leftover-temp check counts only directories this test run created, so a concurrent
   process cannot fail it, and it still fails when the adapter leaks one.

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: exclusions and judging hide only what they were written for
  Scenario: an OS-object exclusion applies inside a user profile only
    Given a readable file whose path repeats an excluded folder name outside any user profile
    When the volume is mapped
    Then that file is listed, and the same path inside a user profile is not

  Scenario: a row with no size is judged, never assumed
    Given an export row with the reparse attribute and an empty size
    When the adapter lists the volume
    Then a link is excluded, an unreadable entry fails the volume, and a plain file is listed

  Scenario: a concurrent process cannot make the gate fail
    Given another process creates an estate-map temp directory while the tests run
    When the gate runs
    Then it still passes, and it still fails when the adapter itself leaks a directory
```
