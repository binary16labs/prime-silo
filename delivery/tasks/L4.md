# L4 — Delta engine (per-content-hash cursors)

## Goal

Every stage processes only what changed since its last run, keyed by a per-content-hash cursor keyed on
(stage, input_content_hash, code_commit, config_hash). Unchanged content at the same code+config is never
reprocessed; re-running is idempotent and resumable; out-of-order arrival across machines is tolerated
because HLC valid-time resolves true sequence. Extends LONGVIEW --delta + phase isolation. R8–R11.

## Context pointers (never inline content)

- Design: architecture/SOLUTION-longview-self-learning.md §4.3 + §5.3 (cursor_advanced record); steer 3
- Cursors are cursor_advanced KEL events (fold via L0's kel.mjs) — no separate store
- HLC ordering: SOLUTION §5.6; requirements R8–R11

## TDD plan

1. Skip test red: an input whose (hash, commit, config) has a done cursor is not reprocessed.
2. Idempotence test: running a stage twice on the same input converges to one done cursor, same outputs.
3. Resume test: an interrupted run resumes from the last durable cursor without redoing completed inputs.
4. Ordering test: two sessions arriving out of order resolve to correct valid-time sequence.

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: only what changed is processed, idempotently and order-tolerantly
  Scenario: unchanged content is never reprocessed
    Given an input with a done cursor at the current code_commit and config_hash
    When the stage runs
    Then the input is skipped
  Scenario: a duplicated run converges
    Given a stage run that is executed twice on the same input
    When both complete
    Then there is one done cursor and the outputs are identical
  Scenario: an interrupted run resumes
    Given a stage interrupted after processing some inputs
    When it is re-run
    Then it processes only the not-yet-done inputs and converges to the same state
  Scenario: out-of-order arrival resolves by valid-time
    Given two sessions that arrive in reverse of their real order
    When deltas apply
    Then the resulting sequence follows HLC valid-time, not arrival order
```
