# S8 — retire the tactical scripts behind an elevation broker

## Goal

The administrative actions the 2026-09-13 scripts performed (create the NAS share and ACLs, schedule the catalog
scan, set a home network Private, scope the SSH firewall rule, set Tailscale unattended) become named actions the
Prime-Silo UI requests through a small elevation broker in the desktop host. Each is a signed action with a
recorded outcome, checked before and after, so the owner no longer runs `estate/*.ps1` for routine operation.
**Human-signed** because it gives the product an elevation path.

## Context pointers (never inline content)

- `architecture/SOLUTION-estate-map.md` §4 (tactical scripts are bootstrap only)
- `estate/setup-nas-share.ps1`, `estate/setup-asus-remote.ps1`, `estate/setup-estate.ps1` (the actions to absorb)
- `packaging/desktop/main.js` (IPC pattern), `governance.mjs` (signed action record)

## TDD plan

1. A fixed allowlist of named actions; the broker refuses anything else, including arbitrary commands.
2. Each action has a read-only check that says whether it is needed; an already-applied action is a no-op.
3. The broker requires a signed action id; the outcome (before/after check) is written to the ledger.
4. Once the actions pass on both nodes, the plan records the scripts as retired; the out-of-repo `OneDrive/binary16/estate/*.ps1` headers are updated as housekeeping outside this allowlist.

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: elevation broker
  Scenario: only named actions can be elevated
    When the broker is asked to run an arbitrary command
    Then it refuses and records the refusal

  Scenario: an applied action is a no-op
    Given the nas share already exists with the expected access
    When create-nas-share is requested
    Then the check reports applied and nothing is changed

  Scenario: every elevated change leaves a record
    Given a signed set-network-private action
    When the broker applies it
    Then the ledger holds the before and after check results
```

## Out of scope

Elevating arbitrary scripts; changing security settings not in the named list.

## Handoff

Verifier runs the gate and applies each named action on a machine where it is not yet applied, confirming the
before and after records.
