# T3 — First QLoRA run + honest base-vs-tuned eval

## Goal
Fine-tune the base on Stream A + B (from T2) and prove — with a number, not a claim — that the tuned
model beats its base on a held-out method/agent eval. RAG is held *separate* so we measure the
fine-tune's own contribution, not retrieval. Merge the adapter to GGUF for serving (T4).

## Context pointers (never inline content)
- Inputs: T2 dataset (train + held-out); T0-proven trainer (device string, working ROCm path)
- Base: Qwen2.5-Coder-7B-Instruct (or Qwen3-8B — pick per T0 smoke + eval fit; record the choice)
- Config: QLoRA rank 16, lr 2e-4, packed ~16k ctx (from design plan "Phase 2")
- Eval instrument = KR1.5's instrument: held-out method-style tasks + tool-call correctness, scored
  base vs tuned. Define the rubric BEFORE training (no moving goalposts)
- Design plan: `~/.claude/plans/mellow-tinkering-swan.md` — "Phase 2"

## TDD plan
1. `scripts/gates/t3.py` red: asserts an eval report exists comparing base vs tuned on the held-out
   set with a recorded delta, and a merged GGUF loads. Fails with reason `no_eval` / `gguf_load_fail`.
2. Eval harness first (runs base, produces baseline numbers) — proves the instrument before the run.
3. QLoRA run; re-run eval on tuned; merge → GGUF; gate green only if tuned ≥ base on the rubric.

## Acceptance (BDD)
```gherkin
Feature: the tuned model is measurably better than its base, honestly
  Scenario: the eval instrument exists and scores the base first
    Given the held-out eval set from T2 and a defined rubric
    When the eval harness runs against the untuned base
    Then a baseline score is recorded per task category

  Scenario: QLoRA training completes on the proven trainer
    Given the T2 train split and the T0-proven ROCm device
    When the QLoRA run executes
    Then loss is logged, the run completes, and a LoRA adapter is saved

  Scenario: the tuned model beats base on the held-out set
    Given base and tuned scored by the same rubric with RAG disabled
    When the eval report is generated
    Then the tuned model's aggregate score is >= base and the delta is recorded (no unmeasured claims)

  Scenario: the adapter merges to a loadable GGUF
    Given the trained adapter
    When it is merged and exported to GGUF
    Then the GGUF loads in the target runtime without error
```

## Out of scope
Serving / router wiring (T4), DPO (T5). If tuned does NOT beat base, that is an honest result — log
it, do not tune the rubric to pass.

tuned table per category, the delta, base-model choice, hyperparameters, and dataset provenance.
