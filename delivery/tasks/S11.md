# S11 — a name the node really has is read, not refused

## Goal

Two ways S2 can misreport this node's software are closed, both found by claude-s2-verifier at S2's PASS:

1. **N1 (loud, but total).** `winget list` pads its fixed-width columns by DISPLAY width, while the
   parser slices by UTF-16 code unit. One CJK, Hangul or full-width character in an application name
   ends its column early, the bleed check fires, and the WHOLE winget source fails every sweep for
   ever with no recovery path. Non-ASCII correctness is the stated reason the export is read from a
   UTF-8 file at all, so a name this node really has must be read, not refused.
2. **The registry fold (silent).** The verifier's closing note: `registry` is the one source with no
   identity of its own, so two Uninstall entries sharing a DisplayName AND DisplayVersion across
   HKLM, WOW6432Node and HKCU fold into one row on S0's (name, version, source) key and one install
   disappears in silence. This is the same class S2 closed for winget and appx and left open here;
   under the owner's directive (2026-09-14) a silent loss is the blocking shape, so it is fixed with
   N1 rather than logged. t480 has 65 distinct registry rows today, so nothing is lost yet.

Also closed, being cheap and on the same line of the parser: **N3**, a non-blank line after the
header that is too short to reach the Version column is currently accepted as an application with an
empty version. A trailing notice from a future winget must fail loudly, never invent an app.
