# T2 — Data pipeline: instruction + trajectory dataset from the corpus

## Goal

Fine-tune quality is ~90% data. Convert the _already-structured_ corpus (LONGVIEW cards, ADRs,
session synthesis, tool-use traces) into training data — the actual moat. Emit two SFT streams,
carve a held-out eval set before any training, and hand-audit a gold subset. Leak-gate every row.

## Context pointers (never inline content)

- Reuse, don't re-derive: `scripts/longview/longview.mjs` + `lib/` (`store.mjs`, `walk.mjs`,
  `card_triples.mjs`, `retrieve.mjs`, `record.mjs`) — the card/graph pipeline
- Privacy gate: `scripts/longview/lib/leak_gate.mjs` — job-application / CV / personal context must
  NEVER enter training rows (memory: `longview_memory_teleport`, operator privacy constraint)
- Agent traces for Stream B: memo-ray store (ingests Claude/Antigravity session + tool-use traces);
  offload orchestrator ledger (ADR-004)
- Design plan: `~/.claude/plans/mellow-tinkering-swan.md` — "Phase 1", Streams A / A' / B

## TDD plan

1. `scripts/gates/t2.mjs` red: asserts JSONL for Stream A + Stream B exist, schema-valid, disjoint
   held-out split recorded, and `leak_gate` reports 0 hits across all rows. Fails with counts.
2. Builder unit tests: one card → a well-formed method/voice pair; one tool-use trace → a
   `(state+goal → next tool call)` row; a seeded CV/job row is REJECTED by the leak gate.
3. Implement `build_dataset.mjs`; dry-run; hand-audit ~200-row gold set; gate green.

## Acceptance (BDD)

```gherkin
Feature: a clean, split, house-voiced training set is produced from the corpus
  Scenario: method/voice pairs are emitted (Stream A)
    Given LONGVIEW cards + ADRs + session synthesis in the corpus
    When build_dataset.mjs runs
    Then it emits JSONL (instruction -> house-style response) pairs that validate against the schema

  Scenario: agent trajectories are emitted (Stream B)
    Given Benny / offload / Claude tool-use traces
    When build_dataset.mjs runs
    Then it emits (state + goal -> next tool call) sequences that validate against the schema

  Scenario: the leak gate blocks personal context
    Given a row derived from job-application or CV session content
    When the leak gate scans the emitted rows
    Then that row is excluded and the gate reports zero personal-context leaks in the output

  Scenario: a held-out eval set is reserved before training
    Given the full emitted set
    When the split runs
    Then a disjoint held-out set is written and never appears in the train split
```
