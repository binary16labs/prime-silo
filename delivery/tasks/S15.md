# S15 — the things two verifiers found after the work was already good enough to ship

## Goal

S4 merged and S13 shipped on the owner's standing decision, each with residuals their final
verifiers named. Three of those residuals are cheap, and two of them are **claims in the tree that
are not true** — which is the defect class both contracts existed to end, so they do not get to
survive as declared limits.

This contract closes exactly what `claude-s4-verifier-7` and `claude-s13-verifier-7` listed as
minutes-not-a-round, and corrects two statements I wrote that a verifier disproved.

## What is wrong now

1. **The lock is a signal, and it is named after the gate.** `coordination/estate/.s3-gate.lock`
   sits in the same directory as the policy the guard reads, so `exists(lock) ? reader() : []` is
   honest under the gate and inert everywhere else — the easiest "am I being audited?" flag in the
   design, added by the round that was meant to remove them.
2. **`dropLock` runs after the final restore**, so every run leaves the estate directory dated now:
   measured 365.000 d → 0.000 d on all three exit paths. My log line said timestamps are restored.
   That is false for the directory, and it is the one timestamp the M4 defence depends on.
3. **An interrupted run can leave the owner's real coordination directory holding the gate's
   synthetic policy**, plus a stale lock that red-lights every later run because the holder's pid is
   never checked for liveness. A gate that fails a correct product is a defect this contract already
   named once.
4. **The backdate and the payload are constants.** 97 days exactly, `digest` of sixty-four `a`s, a
   fixed `sweep_id` prefix: each is a signal common to all three boot shapes, so all three are wrong
   together and the agreement check stays silent. The limits block claims the roundness of thirty
   days was the signal; exactness was.
5. **The clipping comment in the panel's tests is false.** It says clipping is the only way an
   approved declaration puts content out of reach. `.em__card { position: absolute }` stacks
   fourteen cards at one point with one readable, no clipping property involved.
6. **The panel's headline sentence is asserted nowhere.** Hard-coding `reportingLine()` to
   "3 nodes reporting", making it ignore `allStale`, or forcing every badge to read LIVE each ships
   green — while the tests' own comments cite "a header still reading 14 nodes reporting" twice as
   what made earlier defects damning.

## TDD plan

1. Move the lock outside `coordination/`, and drop it BEFORE the final restore rather than on exit.
2. Check the recorded pid for liveness before refusing; handle SIGINT and SIGTERM by restoring the
   estate and dropping the lock.
3. Jitter the backdate, and randomise the digest, snapshot, sweep_id and counts per push.
4. Rewrite the two limits-block entries that overstate: the age claim, and "the three shapes the
   estate implements" → the three that have been found.
5. Correct the clipping comment to say what it can support, and name `position` as a second way.
6. Assert the header and the per-card badge in the render tests that already build those folds.
