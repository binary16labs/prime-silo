# S15 — the things two verifiers found after the work was already good enough to ship

## Goal

S4 merged and S13 shipped on the owner's standing decision, each with residuals their final
verifiers named. Three of those residuals are cheap, and two of them are **claims in the tree that
are not true** — which is the defect class both contracts existed to end, so they do not get to
survive as declared limits.

This contract closes exactly what `claude-s4-verifier-7` and `claude-s13-verifier-7` listed as
minutes-not-a-round, and corrects two statements I wrote that a verifier disproved.

## What is wrong now

Four residuals `claude-s13-verifier-7` measured, set out in full in LOG.md:

1. **The lock is a signal named after the gate.** `coordination/estate/.s3-gate.lock` sits beside the
   policy the guard reads, so `exists(lock) ? reader() : []` is honest here and inert everywhere else
   — the easiest audit flag in the design, added by the round meant to remove them.
2. **`dropLock` runs after the final restore**, so every run leaves the estate directory dated now:
   365.000 d → 0.000 d on all three exit paths. My log said timestamps are restored. False for the
   directory, and it is the timestamp the M4 defence depends on.
3. **An interrupted run can leave the owner's coordination directory holding the gate's synthetic
   policy**, plus a stale lock that red-lights every later run.
4. **The backdate and the payload are constants** — 97 days exactly, a fixed digest and sweep-id
   prefix — each shared by all three boot shapes, so all three go wrong together and the agreement
   check stays silent.

The panel's two leftovers are **S16**: they live on files that reached main with S4 while this
contract's file is still on `task/S13`, and a branch cannot fix code it does not contain.

## TDD plan

1. Move the lock outside `coordination/`, and drop it BEFORE the final restore rather than on exit.
2. Make the lock's holder self-evidently alive — a bound socket dies with its process, where a pid in
   a file has to be checked and the first version never checked it — and handle SIGINT and SIGTERM by
   restoring the estate and releasing it.
3. Jitter the backdate, and randomise the digest, snapshot, sweep_id and counts per push.
4. Rewrite the two limits-block entries that overstate: the age claim, and "the three shapes the
   estate implements" → the three that have been found.
5. Recover, rather than prevent, what a hard kill cannot handle: record what the run displaces
   beside the lock, and put it back on the next run.
