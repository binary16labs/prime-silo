# L5 — Unified execution register (executions.jsonl), backfilled

## Goal

One queryable execution store — a JSONL projection folding G0 run-events + EP-T train-result JSONs +
the LONGVIEW ledger + the B0 coordination ledger + KEL lineage into one schema, backfilled once so
cross-machine comparability ("same task, model A on machine X vs model B on machine Y — cost/quality
delta") is immediate. Rebuildable = replay. R12–R16, R33, R37.

## Context pointers (never inline content)

- Design: architecture/SOLUTION-longview-self-learning.md §4.4 + §5.4 (record shape, why JSONL-not-DB, DuckDB fallback)
- Fold sources: runs/<id>/events.jsonl (G0), scripts/train/eval/out/*.json, LONGVIEW ledger, coordination/tasks.jsonl
- Config tag (model/hw/commit/watermark/hparams) + metrics (wall/tokens/cost/util/quality) + lineage per record
- Requirements R12–R16, R33, R37; steer 4

## TDD plan

1. Projection test red: folding a fixture of the four sources yields one record per execution with required fields.
2. Backfill test: a historical fixture backfills deterministically (same input → same executions.jsonl).
3. Comparability test: an R16 query filters by kind+machine+model_id and returns a cost/quality delta.
4. Rebuild test: deleting and re-folding reproduces the register byte-for-byte (rebuildable projection).

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: every execution is one queryable, comparable record
  Scenario: four logs fold into one schema
    Given fixtures of a G0 run, a train JSON, a LONGVIEW ledger entry, and a coordination event
    When the register is projected
    Then each execution is one record carrying config tag, metrics, lineage, and source_log provenance
  Scenario: cross-machine comparison answers the R16 question
    Given executions of the same kind on machine X and machine Y with different models
    When the register is queried by kind and model
    Then a cost and quality delta is returned
  Scenario: the register is a rebuildable projection
    Given an existing executions.jsonl
    When it is deleted and re-folded from the four source logs
    Then the result is identical
```

## Out of scope

The DuckDB index (deferred, measure-first — only if the fold is proven too slow). The dashboard view
(L14). Serving/promotion records (L6/L12). Folding + backfill + query only.
