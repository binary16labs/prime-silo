# S32 — levels: fingerprint only what a question needs

**Split out of S23 on the owner's decision of 2026-11-15** ("Split it out"). The scope is S23's Part 2
as the owner signed it on 2026-10-11; its signed text is not copied here (contract size) but pointed to,
and its Scenarios and criteria below are binding. Waits on S23. Band L, 800.

## Goal

A new drive is catalogued by reading only the files a question could need: a file whose size
nothing else on the drive shares is never read to find duplicates, and every fingerprint made is kept.

## Context pointers (never inline content)

  shipped" items 1–3; Design item 4 (online-only from Everything's attributes) and Part 2 items 5–10.

## What to build (the signed design, in one line each)

1. Scopes: rebuildable, tiny (under 4 KB), junk, online-only, owner — catalogued, and only owner files
   are read by a pass.
2. Level 0 listed; level 1 a partial fingerprint for owner files whose size another shares (whole file
   up to 8 MB); level 2 a full fingerprint only on a partial match; each level in listing order.
3. Duplicates stay exact: a full-fingerprint match, as in S21.
4. On demand, and kept: a comparison or check needing a fingerprint computes it once and stores it.
5. `sha256` nullable; rows gain `partial`, `level`, `scope`; an S21/S23 catalogue migrates as level 2
   with nothing re-read. Per-file history only for fully fingerprinted files.

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: fingerprint only what a question needs

  Scenario: a file whose size nothing else has is never read to find duplicates
    Given an owner file whose size no other file on the drive has
    When the drive is catalogued
    Then the file is listed with its size and date, and never read

  Scenario: levelled duplicates equal full-fingerprint duplicates
    Given one drive tree
    When it is catalogued by levels and by S21's full pass
    Then both find exactly the same duplicate sets

  Scenario: rebuildable, tiny, junk and online-only files are catalogued but not read
    Given files in node_modules, under 4 KB, named Thumbs.db, and marked online-only
    When the drive is catalogued
    Then each is listed with its scope and none is read

  Scenario: a fingerprint a comparison needed is made once and kept
    Given a backup file whose size matches an F: file with no fingerprint
    When the backup drive is compared with F: twice
    Then that F: file is read once, the first time, and not at all the second
```

## Pre-registered criteria (measured on the real T480 by the verifier, reported either way)

- A full first pass (levels 0–2) of F: in **≤ 3 h**, against 7 h 55 m for S21's full fingerprint.
  The author's estimate is about 2 h. If it misses, the report attributes the time.
- Duplicate sets among owner files equal those of a full-fingerprint catalogue of the same F:
  (the owner's S21 catalogue if one exists by then, otherwise a verifier's full pass).
- A real comparison run twice: the second run reads 0 bytes of F:.
