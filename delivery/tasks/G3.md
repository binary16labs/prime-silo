# G3 — Workflow types catalog + guided customization

## Goal
Proven manifests become a catalog of typed workflows: fixed DAG shape + parameter JSON-schema +
human-readable card. Customization = parameters, sources, step toggles within the fixed shape —
never silent DAG growth. A wizard (one decision per screen) and `benny pypes plan` integration
produce byte-identical manifests.

## Context pointers
- Plan §4 G3 card (PLAN-local-power-unified-ui.md:291-298); seed types listed there (Ingest&enrich, Deep report, Book, Audio overview, Dev pack, Knowledge pack, Enterprise report)
- The 267 MB planner-blowup guard: schema-level DAG-freeze + step ceiling (default ≤12) at validation
- Agent-assisted authoring drafts into agent_sandbox/ only; human signs/executes (ADR-001)

## TDD plan
1. Red: every catalog entry instantiates with example params → validates + dry-runs green.
2. Red: over-ceiling or shape-mutating agent draft fails validation.
3. Implement catalog + validation — green. 4. Wizard/CLI byte-parity test.

## Acceptance
```gherkin
Feature: workflows are products with fixed shapes
  Scenario: the whole catalog instantiates
    Given every type and its example parameters
    Then each produces a validating manifest that dry-runs green

  Scenario: wizard equals CLI
    Given the same type and parameters entered via wizard and via CLI
    Then the produced manifests are byte-identical

  Scenario: planner blowup is structurally impossible
    Given an agent-drafted workflow exceeding the step ceiling or mutating a template DAG
    Then validation rejects it and the draft stays in agent_sandbox
```

## Out of scope
Visual DAG editing (H-deferred), R2/R3 catalog entries (added by those tasks).
