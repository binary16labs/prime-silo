# A0 — Verify the real local offload path (currently UNVERIFIED)

## Goal

Prove ADR-004's offload orchestrator end-to-end against real qwen3.5-9B-FLM @16k — sync MCP path and
async runner — with a wedge watchdog and evidence-seeded judge calibration. All of EP-A builds on this
being true rather than assumed.

## Context pointers

- Plan section 2, A0 card; branch feat/local-offload-orchestrator (17/17 unit tests, real path never run)
- Measured reality (architecture/REVIEW-longview-cards-2026-07-05.md): TTFT 22s at 7.7k input, 8.33 tok/s, 500-tok output proven; 120s silence watchdog correct — do not lower
- 16k load: recipe_options.json + POST /api/v1/load (never chat immediately after killing flm.exe)
- Judge seeds: known-bad = invalid/truncated JSON, path-mangled output, context overflow; acceptance = operator profile (explicit, actionable errors, validated)
- Wedge (compute-aware, 2026-07-05 silence!=wedge incident): token silence + BUSY compute (lemonade stats or OS perf counters + flm.exe CPU delta) = prefill_in_progress (wait, heartbeat, ~15 min hard ceiling); silence + IDLE compute = wedge_suspected, honest ledger entry; flm.exe PID change logged as model_restarted (reset clock). NEVER auto-restart the service

3. Gate a0.py: real sync offload_exec + real async run of a trivial example manifest; judge verdict recorded, resolved-workspace line logged, wall time < 5 min; exits 1 reason=service_down if lemonade unreachable.

## Acceptance

```gherkin
Feature: the local execution path is proven, not presumed
  Scenario: sync and async paths complete against the real model
    Given lemonade serving qwen3.5-9b-FLM with ctx 16384
    When a trivial example manifest runs via offload_exec and via the async runner
    Then both produce judged results recorded in an honest ledger entry within 5 minutes

  Scenario: a wedged generation is detected, reported, never auto-fixed
    Given a generation emitting no tokens for 120 seconds AND idle compute on the model process
    When the watchdog fires
    Then the run is classified wedge_suspected with a ledger entry and non-zero exit
    And the lemonade service is not restarted by the runner

  Scenario: long prefill is not misclassified as a wedge
    Given a generation emitting no tokens for 120 seconds while the compute probe reports busy
    When the watchdog evaluates
    Then the state is prefill_in_progress with a heartbeat log line, and only a ~15-minute hard ceiling escalates it

  Scenario: model process respawn is observable
    Given the flm.exe PID changes mid-run
    Then a model_restarted event is logged and the watchdog clock resets

  Scenario: judge is calibrated on measured failure modes
    Given 5 known-good and 5 known-bad fixtures including invalid JSON, path-mangled, and context-overflow
    When the judge evaluates all 10
    Then all 10 verdicts match their labels

  Scenario: service down is an honest failure
    Given lemonade is unreachable
    When the gate runs
    Then it exits 1 with reason service_down and marks nothing as passed
```
