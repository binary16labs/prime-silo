# L7 — Single-winner loop claim + compaction budget

## Goal

Concurrent machines claim a loop turn under an exactly-once (single-winner) protocol so two machines
never train/merge against the substrate simultaneously — by reusing the B0 `wx` atomic-lease claim,
not a new mechanism. Plus a stated storage/compaction budget (append-only on a finite drive), with
compaction itself additive and journalled. R43 + R42.

## Context pointers (never inline content)

- Design: architecture/SOLUTION-longview-self-learning.md §4.5 (single-winner) + §4.7 (compaction budget)
- Reuse verbatim: server/coordination/lib/ledger.mjs lease protocol (leases/<task_id>.json, wx create, 15-min expiry/heartbeat)
- Well-known claim id: flywheel-turn; requirements R43 (exactly-once), R42 (compaction)

## TDD plan

1. Claim-race test red: N concurrent claimants on flywheel-turn → exactly one winner, losers walk away.
2. Expiry test: a stale lease (expires_at past) is reclaimable, still exactly one winner after the race.
3. Compaction test: compaction is journalled and additive — pre-compaction state is reconstructable.
4. Budget test: storage crossing the configured budget raises a flagged warning (not a silent collision).

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: exactly one machine runs a loop turn; growth is budgeted
  Scenario: only one machine wins the turn
    Given many machines racing to claim flywheel-turn
    When they claim concurrently
    Then exactly one acquires the lease and the rest get already-claimed
  Scenario: a stale lease is reclaimable, still single-winner
    Given a flywheel-turn lease whose expiry is past
    When machines race to reclaim it
    Then exactly one wins
  Scenario: compaction loses nothing
    Given a substrate that is compacted
    When the journal is replayed
    Then the pre-compaction state is reconstructable
  Scenario: growth past budget is flagged, not silent
    Given storage crossing the configured budget
    When the budget check runs
    Then a warning is raised naming the overage
```
