# S22 — Benny the librarian: the agent answers from the catalogue

## Goal

The owner asks Benny, in Prime-Silo's own chat, "where are my 2019 holiday photos?", "what is
wasting the most space on F:?" or "is this folder already on F:?". Benny answers from S21's
catalogue, with the owner's privacy rules applied, and never reads F: to do it. The same three
questions are available to agents outside the app (Claude Code, the local agent stack) through
the `prime-silo-nexus` MCP server. This is the second half of the owner's 2026-10-03 directive:
"first … a librarian of the files and the store", then "the local agent helps manage it". Answers
only: nothing is moved, deleted or catalogued by the agent (see Out of scope).

## Design (the author may refine it; the Scenarios are normative)

1. **One place judges privacy: the hub.** Three read-only query routes are added beside S21's.
   Each is loopback only and refused (412) without a policy, and every path it returns has passed
   the quarantine rules:
   - `GET /api/estate/library/find?root=F:&q=<text>&kind=<kind>&limit=50`: files whose path
     contains the text (case-insensitive), optionally of one kind. Returns size, mtime and kind,
     plus how many matches were private (counted, not named).
   - `GET /api/estate/library/duplicates?root=F:&offset=0&limit=20`: duplicate sets beyond S21's
     top 10, the most wasted first, with the same counting rule.
   - `POST /api/estate/library/check { path }`: is this file, or every file under this folder (on
     any drive this machine can read), already on F:? It reads only the given path, never F:. It
     uses S21's comparison rule: size first, then full hash, and a match counts only if the F:
     file still has its catalogued size and mtime. It answers per file (on F: at <paths> /
     changed since catalogued / not on F:), with a cap on the number of files and a total, and
     names the catalogue's time.
2. **No catalogue is not "not on F:".** A drive without a finished catalogue makes every query
   answer with the reason ("F: has no finished catalogue"), never an empty list.
3. **The in-app skill (`librarian`)** is a catalog-loaded skill like `benny-pilot`: a `SKILL.md`
   saying when to load it and how to answer (lead with the answer, sizes in human units, say how
   many results were withheld as private and never guess at them, say the catalogue's age), and a
   helper module with `find`, `duplicates`, `check` and `status` (the S21 `GET /library`). The
   helpers are same-origin fetches to the routes above; the skill never touches the file system
   itself.
4. **MCP tools** `library_find`, `library_duplicates`, `library_check` are thin clients of the same
   routes. When the hub is down they say so ("the Prime-Silo hub is not running") and do not fall
   back to opening the SQLite file. A direct read would be a second place where privacy is
   judged.
5. **Read-only for the agent.** Neither the skill nor the MCP tools can start or stop a catalogue
   pass, change the catalogue, or move or delete anything. The skill tells the owner which button
   to press (Library tab → Catalogue F:) when the catalogue is missing or old.

## Prime-Silo and Benny compliance, and the local config (owner, 2026-10-10)

The owner signed S22 on the condition that it "has to be Benny and Prime-Silo compliant and handle
the local config". These rules make that condition checkable. They also cover gaps S21 left: S21
hardcodes `F:/estate-store` and reads it from raw `process.env`, and it changed `server/` without
the documentation the server rules require.

6. **The store location is a declared runtime parameter, not a literal.** `ESTATE_STORE` (and
   `ESTATE_SWEEP_ROOTS`, which S17 already reads from raw `process.env`) are added to
   `commands/params.yaml` with a description, a type and an empty default. They resolve through
   `server/lib/utils/runtime_params.js` with Prime-Silo's precedence (launch override, then the
   stored `.env`, then the process environment, then the schema default), are shown by
   `node space get`, and are set with `node space set ESTATE_STORE=F:/estate-store`. `server/app.js`
   passes the resolved value to the estate API as `producer.libraryDir`. The `F:/estate-store`
   literal in `estate_api.mjs` is removed: a machine path is never a default shipped to every
   install (the ASUS and the Pi have no F:).
7. **Unset is said, not guessed.** With `ESTATE_STORE` empty, every library route answers
   `{ error: "ESTATE_STORE is not set — run: node space set ESTATE_STORE=<folder>" }`. The panel's
   Library tab then shows "This machine cannot catalogue: …" through S21's existing error path,
   and the skill and MCP tools relay the same sentence. Setting it on the T480 is the owner's step
   (agents do not change configuration, per AGENT-AWARENESS.md): see Handoff.
8. **The MCP server finds the hub from the local config.** The hub URL is `PRIME_SILO_API` if set.
   Otherwise it is built from the project `.env` (`HOST`, `PORT`), read with the shared
   `server/lib/utils/env_files.js` helpers rather than a second parser, with `0.0.0.0` read as
   `127.0.0.1`. `PORT=0` means the port cannot be known from config, and the tools say so. Every
   tool answer names the hub it asked and where that address came from (e.g. "hub
   http://127.0.0.1:3000, from .env"). A foreign or stale `.env`, like the ASUS one that once
   pointed Benny at a D: home and the wrong subnet, is then visible in the answer rather than
   silently queried. `BENNY_API_KEY` resolution in `mcp/server.js` is unchanged.
9. **Agent authority as Prime-Silo states it.** The skill and the tools are read-only queries, as
   AGENT-AWARENESS.md requires of agents: they do not execute, mutate catalogues or change config.
   AGENT-AWARENESS.md gains a "Files catalogue (librarian)" section under Querying System State
   listing the skill, the three MCP tools, what they answer and what they refuse.
10. **Every agent question is audited, without its words.** Each query from the skill or MCP leaves
    one `library_queried` event in that drive's library log (S21's `.jsonl`). It records the
    surface (skill or mcp), the question kind (find, duplicates or check), counts returned and
    withheld, and the catalogue pass it was answered from. It never records the query text or a
    path, because "find my CV" is itself private.
11. **Documented where the server rules say.** Per `server/AGENTS.md` ("after any change under
    `server/` … update the relevant supplemental docs under
    `app/L0/_all/mod/_core/documentation/docs/`"), a new `docs/server/estate-library.md` documents
    the library routes (S21's and S22's), their guards (loopback, policy, store parameter),
    response shapes and the privacy rule. `docs/agent/skills-and-documentation.md` lists the
    `librarian` skill.

## TDD plan

1. `library_test`: `findFiles(dbPath, root, rules, {q, kind, limit})` matches case-insensitively
   and by kind, counts private matches and names none. `checkPaths(...)` gives on F: / changed since
   catalogued / not on F:. F: file data is never opened (hasher spy), and the given folder is
   walked only up to the cap.
2. Routes: find, duplicates paging and check answer loopback only, give 412 with no policy, give
   "no finished catalogue" rather than empty, and keep private paths out of every JSON body.
3. `librarian_skill_test`: the skill is discoverable where onscreen discovery looks, has valid
   frontmatter, is catalog-loaded not auto-loaded, its helper exports
   `find/duplicates/check/status`, and every helper URL is one of the routes above. A guard like
   S21's panel test reads the URLs out of the source.
4. `librarian_mcp_test`: the three tools are listed, with input schemas. Against a test hub each
   one returns the hub's answer. With no hub listening, each says the hub is not running, and none
   opens a `.db` file (fs spy).
5. Config: `ESTATE_STORE` resolves by the documented precedence (a launch override beats `.env`,
   which beats the process environment), `node space get` lists it, and an empty value gives the
   "not set" answer on every library route. The MCP hub URL comes from `PRIME_SILO_API`, then
   `.env` `HOST`/`PORT` (`0.0.0.0` read as `127.0.0.1`), and the answer names that source; `PORT=0`
   is refused with its reason.
6. Audit: one `library_queried` event per agent question, with counts and no query text or path
   (a test with a private query string searches the log bytes for it).
7. Docs: a test fails if `estate-library.md` does not name every `/api/estate/library*` route the
   API serves (read from `estate_api.mjs`), and if AGENT-AWARENESS.md does not list the skill and
   the three tools.
8. Gate `s22.mjs`: runs the S22 test files, then the S21 gate (shared library, API and panel) and
   the B2 gate (shared `mcp/server.js`).

## Owner questions (answer before signing)

1. **Names to outside agents.** The MCP tools can be called by agents whose answers leave this
   machine (Claude Code in the cloud), and agent traces can be harvested for training (EP-A). The
   rules withhold private paths either way. Should the MCP tools return file names at all?
   Recommendation: yes, rule-filtered, matching what the panel already shows. The alternative is
   counts and sizes only over MCP, with names only inside the app.
2. **Scheduling rescans.** Left out of S22 on purpose. The S21 verifier is measuring how long a
   rescan of an unchanged F: takes. That number decides between a nightly rescan and Everything
   1.5's change journal, and it gets its own contract (S23) once it is known.

## Out of scope

- Moving, deleting or de-duplicating anything (S7, human-signed).
- Cataloguing drives other than those S21 catalogues; other machines.
- Semantic search over file contents (the catalogue holds names, sizes and hashes, not text).
