# S4 — the Estate Map panel in the Prime-Silo UI

## Goal

A Prime-Silo panel `_prime_silo/estate_map`, registered like the Release panel, that renders the folded estate
map from `/api/estate/map*` only: machine cards (online, Prime-Silo version, volumes, map age), a storage treemap
(machine -> volume -> category), an applications-by-machine matrix with version drift highlighted, and media
roots. This replaces running report scripts to see the estate.

## Context pointers (never inline content)

- `architecture/SOLUTION-estate-map.md` §5
- `app/L0/_all/mod/_prime_silo/release/` (panel yaml, view.html, js, css pattern)
- `server/pages/estate.html` (EP-N console: theme and motion conventions)

## TDD plan

1. Panel yaml registers `_prime_silo/estate_map`; the view loads with the API mocked.
2. Treemap layout is a pure function of fold data (tested without a DOM); areas sum to used bytes.
3. Stale machines render as stale with their age; they are never hidden or shown as empty.
4. Version drift: two machines on different Prime-Silo versions are flagged in the matrix.

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: estate map panel
  Scenario: the panel shows both nodes from the fold alone
    Given a fold with t480 online and optimus stale since 10:00
    When the panel renders
    Then two machine cards appear and optimus reads "stale since 10:00"

  Scenario: version drift is visible
    Given t480 runs Prime-Silo 1.24.5 and optimus runs 1.24.4
    When the applications matrix renders
    Then the Prime-Silo row is flagged as drifted

  Scenario: the treemap accounts for every byte it shows
    Given a volume with categories summing to 812 GB used
    When the treemap is laid out
    Then the rectangle areas are proportional and sum to 812 GB
```
