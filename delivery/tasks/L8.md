# L8 — Bi-temporal projectors + time-travel query

## Goal

Fold the knowledge event log to rebuild the stores as projections, applying the L0 up-converter
registry, and answer both "what was true at T" (valid-time) and "what did we know at T"
(transaction-time) — including reconstructing the exact knowledge state that produced an artifact
(e.g. the corpus a model trained on). Projection is incremental via L4 cursors; rebuild-from-log is
the replay guarantee. R1–R3, R7, R32.

## Context pointers (never inline content)

- Design: architecture/SOLUTION-longview-self-learning.md §4.1 (projection) + §5.1/§5.6 (envelope, converters); steers 1/10
- Inputs: L0 kel.mjs (fold + converters), L4 delta.mjs (incremental cursors)
- Card projection (JSON on disk) is the reference sink proving the engine; Neo4j/Chroma/memo-ray adapters
  conform to the same projection-sink interface (thin, additive — never replace the live write path, R36)
- Requirements R1–R3, R7, R32

## TDD plan

1. Rebuild test red: folding a fixture KEL reproduces the card projection; delete + re-fold is identical.
2. Valid-time test: query at valid_time T returns the world-state true at T, ignoring later corrections.
3. Txn-time test: query at txn_time T returns what the system had recorded by T (knowledge-as-of).
4. Corpus-reconstruction test: given a model's knowledge_watermark, the exact input state is rebuilt.
5. Incremental test: a single changed session reprojects only affected records (via L4 cursors), not all.

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: projections are rebuildable and time-travellable off the log
  Scenario: a projection rebuilds from the log alone
    Given a KEL fixture and its card projection
    When the projection is deleted and re-folded
    Then the result is identical (rebuildable = replay)
  Scenario: what was true at T (valid-time)
    Given events later corrected
    When the projection is queried at valid_time T
    Then it returns the state true in the world at T, not the later correction
  Scenario: what did we know at T (transaction-time)
    Given events recorded across several transaction times
    When the projection is queried at txn_time T
    Then it returns only what had been recorded by T
  Scenario: reconstruct the corpus a model trained on
    Given an execution record with a knowledge_watermark
    When the state is rebuilt at that watermark
    Then it equals the exact input knowledge state of that training run
  Scenario: a change reprojects incrementally
    Given one changed session
    When projection runs
    Then only the affected records are rebuilt, not the whole store
```
