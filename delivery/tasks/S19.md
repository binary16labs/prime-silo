# S19 — duplicates and sole copies across machines

## Goal

For files under folders the owner has named, the estate knows which content is held on more than
one device and which on exactly one — judged by hash, never by name — and S5's coverage counts them.

## Context pointers (never inline content)

- `server/coordination/lib/estate_map_fold.mjs` — the wire's allowlist, which carries counts only
- `server/coordination/lib/estate_integrity.mjs` — S5's coverage, which this extends by hash
- `architecture/SOLUTION-estate-map.md` §2 (tiered hashing), §7 (integrity is honest)

## What is wrong now

The map's wire carries counts, deliberately (S3), so the hub cannot see that two machines hold the
same file. Duplicates found on one machine alone say nothing about whether the estate has a copy.

## TDD plan

1. Node: size collisions among named files only, then a partial hash (first and last 4 MB plus size),
   then a full hash on a partial match; stored in the node's index.
2. Wire: a push may carry content records — hash or partial, size, volume — and nothing else: no
   path, no name. The hub's allowlist refuses anything more, and bounds the count.
3. Hub: fold content to distinct devices. Full hash on two or more devices is a duplicate; on one,
   a sole copy; a partial match only is "suspected" and is never counted as either.

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: content across the estate
  Scenario: a partial match is suspected, not a duplicate
    Given two 30 GB files whose partial hashes match and whose full hashes were not computed
    When the estate is folded
    Then both are "suspected" and neither counts as a duplicate or a sole copy

  Scenario: the same file on two machines is covered twice
    Given one file, fully hashed, under named folders on t480 and on the ASUS
    When the estate is folded
    Then it is a duplicate with coverage 2

  Scenario: a content record that carries a name is refused
    Given a push whose content record includes a path
    When the hub judges it
    Then the whole push is refused (R31) and nothing is recorded
```

## Out of scope

Acting on findings (S6, S7); hashing files outside named folders.

## Handoff

Human-signed because it widens the wire. A hash of a known file shows that a machine holds it, so
only named folders are hashed, and naming one is the owner's act (S18). The verifier smuggles a
path, a name and an unbounded record list into a push and confirms each refuses the whole push.
