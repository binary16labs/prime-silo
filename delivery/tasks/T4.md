# T4 — Wire the tuned model behind Benny's router + drive the offload gate

## Goal

Make the tuned model a **candidate engine behind Benny's existing router** (additive — never replaces
the current engine) and prove it drives a real task through the ADR-004 offload gate with RAG
grounding, no regression vs the current engine. This is where EP-T pays off into O1.

## Context pointers (never inline content)

- Serve merged GGUF (from T3) via LM Studio/lemonade; Benny multi-endpoint router (memory:
  `longview_network_lmstudio_repoint_v4`, proven repoint `192.168.68.125:1234`)
- Offload path: ADR-004 orchestrator + green/yellow/red judge gate (EP-A / A0 DONE — reuse, don't
  rebuild); honest ledger/digest discipline
- RAG stays the fact source: S16/LONGVIEW retrieval unchanged at inference
- Design plan: `~/.claude/plans/mellow-tinkering-swan.md` — "Phase 3"

## TDD plan

1. `scripts/gates/t4.py` red: asserts the tuned engine is registered as a router candidate (existing
   engine still default), and a trivial offload task completes through the gate with a judged result.
2. Router unit tests: candidate registration is additive (default engine unchanged when tuned engine
   absent/unhealthy → falls back, never hard-depends).
3. Run one real offload task via the tuned engine, RAG on; compare to current-engine baseline.

## Acceptance (BDD)

```gherkin
Feature: the tuned model serves behind the router as an additive, RAG-grounded engine
  Scenario: the tuned engine is an additive candidate
    Given the merged GGUF served and registered in Benny's router
    When the router config is inspected
    Then the current engine remains the default and the tuned engine is an opt-in candidate

  Scenario: a real task runs through the offload gate on the tuned engine
    Given the tuned engine selected and RAG grounding enabled
    When a trivial dev task runs via the ADR-004 offload orchestrator
    Then it produces a judged result in an honest ledger entry, no regression vs the current engine

  Scenario: unhealthy tuned engine falls back, never hard-fails
    Given the tuned endpoint is down
    When a task is routed
    Then the router falls back to the current engine and logs the fallback (no crash)
```
