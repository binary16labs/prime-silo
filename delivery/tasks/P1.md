# P1 — Real executor hook — where the zeros end

## Goal

`run_multi_model` carries eight agentic metrics and has never produced a real one: `hook` defaults
to `_dry_run_stub`, which returns `0.0` for every field. Supply a real hook that drives a subject
through the SDLC manifest, and make **`unmeasured` structurally distinct from `0.0`** (R1–R3).

## Context pointers

- Design: `architecture/SOLUTION-model-plurality.md` (requirement → component map §4.6)
- Requirements: `architecture/REQUIREMENTS-trained-model-workflows.md` (R numbers cited inline)
- Reuse `model_resolver.resolve_model()`'s existing per-persona map; never add a second resolver

## TDD plan

1. Red: `hook=None` RAISES rather than silently selecting the stub.
2. Red: an underivable metric is `None`; a mutation coercing it to `0.0` turns the gate RED.
3. Red: an unreachable subject yields `unavailable` with a reason while the other subjects complete.

## Acceptance

```gherkin
Feature: the harness measures, or says that it did not
  Scenario: an underivable metric is never reported as zero
    Given a subject whose token accounting is unavailable
    When the bench runs
    Then that metric is unmeasured and excluded from ranking

  Scenario: an unavailable subject does not abort the run
    Given one subject whose endpoint is down
    When the bench runs
    Then that row is unavailable with a reason and the others complete
```
