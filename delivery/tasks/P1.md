# P1 — The metric schema: unmeasured is not zero

## Goal

`run_multi_model` carries eight agentic metrics and has never produced a real one: `hook` defaults
to `_dry_run_stub`, which returns `0.0` for every field, so an underived metric and a genuine zero
are the same bytes in the report. Make **`unmeasured` structurally distinct from `0.0`** (R1–R3),
and make the silent stub unreachable by accident.

Split from the original P1 on 2026-08-04 (owner decision): that contract measured 673 lines against
a budget of 550. This half is the schema and the runner; `P6` is the executor that fills it in.

## Context pointers

- Design: `architecture/SOLUTION-model-plurality.md` §4.2, decisions D3 and D4
- Requirements: `architecture/REQUIREMENTS-trained-model-workflows.md` (R1, R2, R3, R22, R23)

## TDD plan

1. Red: `hook=None` RAISES rather than silently selecting the stub.
2. Red: a fresh `SandboxResult` reports every metric as `None`; a mutation coercing any to `0.0`
   turns the gate RED.
3. Red: an unreachable subject yields `unavailable` with a reason while the other subjects complete,
   and reports no metrics at all.

## Acceptance

```gherkin
Feature: the harness measures, or says that it did not
  Scenario: an underivable metric is never reported as zero
    Given a subject whose token accounting is unavailable
    When the bench runs
    Then that metric is unmeasured and excluded from ranking

  Scenario: an unavailable subject does not abort the run
    Given one subject whose endpoint is down
    When the bench runs
    Then that row is unavailable with a reason and the others complete
```
