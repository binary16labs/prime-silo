# S3 — nodes push their map, the hub folds one estate map

## Goal

A node publishes its sweep summary and snapshot hash to the hub through the N7 register (the node initiates; the
hub never reaches in), and the hub folds the latest sweep per machine into one estate map served at
`GET /api/estate/map` (machines, volumes, app and media counts, sweep age). **Human-signed** because it widens
the register surface from session manifests to the whole-estate map.

## Context pointers (never inline content)

- `architecture/SOLUTION-estate-map.md` §1 (push direction), §7 (no false outages)
- `server/coordination/lib/estate_register.mjs` (shared-key check, LAN gate, R31 payload guard)
- `scripts/estate_satellite_agent.mjs` (satellite-initiated push)
- `server/coordination/lib/heartbeat.mjs` `isHeartbeatStale` (stale-since, not empty)

## TDD plan

1. Register accepts a `map` payload of counts + snapshot hash only; any field carrying file content or a
   quarantined path is rejected by the existing R31 guard.
2. `foldEstateMap(events)` keeps the latest sweep per machine and volume; an older sweep never overwrites a newer.
3. A machine whose last push is older than the threshold is `stale` with `since`, and its last map is kept.
4. `GET /api/estate/map` returns the fold; `GET /api/estate/map/:machine` returns volumes and top categories.

## Amendment — wire the guard, or refuse the map (owner-signed 2026-09-21)

`server/app.js` is added to the allowlist. claude-s3-verifier's D2: the hub's quarantine rules were
never passed to `createEstateApi`, so in the running product `rules` was always `[]` and every
quarantine branch was dead code while the comment claimed otherwise. The gate could not see it
because the tests construct the API directly with rules supplied. `mapMaxAgeMs` was unwired the same
way, which left the one threshold §7's only S3 criterion rests on unasserted.

Wiring alone would not be enough: an absent or forgotten policy file would put the guard straight
back to inert, silently. So the map surface **fails closed**. The hub accepts a map push only when it
has been given a quarantine policy — an explicit empty list is a policy, an absent one is not. A hub
with no policy refuses map pushes with a reason and keeps serving everything else, including N7
session registration, which is unchanged.

```gherkin
  Scenario: a hub with no privacy policy accepts no map
    Given a hub started without a quarantine policy
    When a node pushes a well-formed map
    Then the push is refused, nothing is recorded, and session registration still works

  Scenario: the product wiring supplies the policy
    When the gate inspects how server/app.js builds the estate API
    Then it passes both the quarantine policy and the staleness threshold
```
