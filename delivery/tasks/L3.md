# L3 — Durability of the portable substrate (replicate + verify + restore drill)

## Goal

R17 makes D: the single point of truth; append-only is not backed up. The staging + KEL substrate must
be replicated to a second local target with periodic checksum integrity checks and a rehearsed restore
drill, so single-drive failure does not lose the corpus. Backup is a local copy, not a cloud dependency
— stays local-first (R21/R34). Extends R41.

## Context pointers (never inline content)

- Design: architecture/SOLUTION-longview-self-learning.md §4.2 (R41 durability)
- Targets a second local path (env-configured); mirrors D:\flywheel-staging\ (blobs + eventlog + index + manifests)
- Integrity = per-blob + per-log-line checksums; restore drill = rebuild a projection from the replica
- Requirement R41

## TDD plan

1. Replication test red: after a stage, the replica contains the same blobs/log lines (byte-identical).
2. Integrity test: a corrupted replica blob is detected by checksum mismatch and reported.
3. Restore-drill test: with the primary removed, a projection rebuilds from the replica alone.

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: the portable substrate survives single-drive failure
  Scenario: the substrate is replicated
    Given a staged session and KEL events on the primary
    When replication runs
    Then the replica holds byte-identical blobs and log lines
  Scenario: corruption is detected, not silent
    Given a replica blob whose bytes were altered
    When the integrity check runs
    Then it reports a checksum mismatch naming the blob
  Scenario: restore works from the replica alone
    Given the primary staging root is unavailable
    When the restore drill rebuilds a projection from the replica
    Then the projection matches the pre-failure state
```

## Out of scope

Cloud/off-site backup (explicitly not — local-first). Compaction (L7). Bi-temporal projectors (L8).

## Handoff

Verifier re-runs `node scripts/gates/l3.mjs` with temp primary+replica fixtures, including the
corruption-detection NEGATIVE case. `docs/operations/FLYWHEEL-DURABILITY.md` documents the restore drill
as a runnable procedure a fresh agent can execute.
