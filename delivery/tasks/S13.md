# S13 — a gate that reads source text can be satisfied while the product is broken

## Goal

The s3 gate stops asserting things about `server/app.js` by reading it as text, and starts asserting
them by **building the real estate API and driving it**. A wording change must not be able to
satisfy the gate while leaving the hub inert.

S3 failed verification twice, and all three findings across those rounds were one fault: **a guard
whose comment described what the author meant rather than what the code did.** Each round fixed the
instance. `claude-s3-verifier-3`'s F1 is the third instance, and it has migrated into the gate that
was supposed to catch the other two:

> appending `?? []` to `app.js`'s quarantine expression keeps the gate GREEN while leaving the hub
> with an empty policy — the exact inert state the D2 amendment exists to prevent.

The gate's check is a prefix match whose comment claims it verifies the policy comes from the
reader. It does not. A gate that can be satisfied while the product is broken is worse than no gate,
because the next author trusts it.

Two narrower findings from the same verification, both cheap and both in this allowlist:

- **F2.** `VOLUME_SEGMENT` and `VOLUME_ROOT` carry `iu`, and Unicode case folding maps U+017F (ſ)
  to `s` and U+212A (K) to `k`, so they pass a rule whose comment says "no non-ASCII". No path can
  hide in them — the consequence is a second volume key for one volume, and a hub rule written as
  the string `users` missing `F:\uſers` — but the comment is again wider than the code.
- **F3.** The satellite agent aborts its **whole** announce, sessions included, when its own map
  payload is refused. The hub-side rule is the opposite and deliberately so: a map that cannot be
  accepted must not stop N7 session registration. The node should mirror it.
