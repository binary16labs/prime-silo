# S5 — integrity: duplicates, sole copies, coverage, verification

## Goal

From the folded map, the estate knows which content exists more than once across machines, which content exists
exactly once (the files at risk), and how many independent devices hold each managed artifact. Managed roots are
periodically re-hashed and each result is an `artifact_verified` event. Every number carries the scope and the
evidence strength it was judged from.

## Context pointers (never inline content)

- `architecture/SOLUTION-estate-map.md` §2 (tiered hashing), §4.1, §7 (integrity is honest)
- `server/coordination/lib/artifacts.mjs` (`artifactVerifiedEvent`, `buildArtifacts`)
- `server/coordination/lib/inventory.mjs` (orphans/unrecorded: shown alongside, not reimplemented)

## TDD plan

1. Candidate selection: size collisions only; partial hash (first + last 4 MB + size), then full hash on match.
2. Classify per content: `duplicate` (full hash, 2+ placements), `sole-copy` (full hash, 1 device),
   `suspected` (size/partial only). `sole-copy` is never asserted from a partial hash.
3. Coverage counts distinct devices, not paths: two copies on one disk are coverage 1.
4. `estate_verify.mjs` re-hashes managed roots; a mismatch emits `artifact_verified ok:false` and is surfaced.

## Amendment — consolidating backup drives (owner directive 2026-09-21)

Owner's use case: _"consolidate all my backups from various drives into this main one, but it should
be safe and deterministic where duplicates are identified and workflows to manage are easy."_ The
owner chose to keep the planned order (S3 → S4 → S5 → S6 → S7) rather than bring a local-only
version forward, and chose **report only, I decide each** as the disposition for a confirmed
duplicate. Recorded here because it adds requirements this contract did not carry.

**A drive that is not attached is not evidence either way.** "Various drives" means external drives
that come and go, and F: already holds machine-shaped trees (`Dell Inspiron 6400`, `lenovo`,
`Optimus`, `backups`, `_Serato_Backup`) from earlier consolidations. Coverage and sole-copy
therefore may never be computed as though an unseen device were empty, nor as though a device last
swept weeks ago still holds what it held then. Every coverage number names the devices it counted
and, for each, when that device was last swept; a device whose last sweep errored or predates the
content's own mtime is reported `stale`, never counted as coverage, and never allowed to make
something "not a sole copy".

**Deterministic means order-independent.** The same content on the same set of devices classifies
identically regardless of the order volumes were swept, which drive was attached first, or which
path a copy was found under. Classification is a function of content and device identity, nothing
else.

Two further Scenarios, both required:

```gherkin
  Scenario: an unattached drive cannot make something safe
    Given content whose only other copy is on a drive that was not swept this time
    When coverage is computed
    Then that device is reported stale, coverage counts it as 0, and the content stays at risk

  Scenario: the same drives in a different order classify the same
    Given the same content across the same devices swept in a different order
    When integrity is classified
    Then every classification, count and identifier is byte-identical to the first run
```
