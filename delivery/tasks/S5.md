# S5 — integrity of what the estate already records: coverage, sole copies, bit rot

## Goal

For every managed artifact the estate has recorded, the owner can see how many independent devices
hold it, which artifacts exist on exactly one device (the files at risk), and whether each copy
still has the bytes it was recorded with. Every number carries the scope it was judged from.

## Context pointers (never inline content)

- `server/coordination/lib/artifacts.mjs` — placements are events; `buildArtifacts`, `placementsOf`
- `server/coordination/lib/nas_catalog.mjs` — the share's catalog: one row per file with its sha256
- `delivery/board/LOG.md` — the 2026-10-03 S5 entry: what was measured before this was rewritten

## TDD plan

1. Coverage from the artifact ledger: distinct DEVICES per artifact, not placements and not paths.
2. A sole copy is an artifact on one device, and the count says which ledger it was judged from.
3. `estate_verify.mjs` re-hashes each placement held on THIS machine; a mismatch writes
   `artifact_verified ok:false` and is surfaced; a placement it cannot read is "unverified", never ok.
4. The NAS catalog's files count as placements on the machine that owns the share.

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: integrity of recorded artifacts
  Scenario: two copies on one device are still at risk
    Given one artifact placed twice on t480 and nowhere else
    When coverage is computed
    Then coverage is 1 and the artifact is flagged as a sole copy

  Scenario: bit rot is recorded, not ignored
    Given a placement whose bytes changed without a placement event
    When verification runs
    Then an artifact_verified event with ok false is written

  Scenario: a copy that cannot be read is not called verified
    Given a placement whose file is missing or locked
    When verification runs
    Then it is reported unverified, and no ok:true event is written
```

## Out of scope

Duplicates found by hashing files the ledger does not record, and anything across machines that the
map's wire does not carry — that is S19, after S18 names which folders may be listed. Acting on
findings (S6, S7).

## Handoff

Verifier runs the gate, then runs verification on the real ledger (F:\estate-store\eventlog) and
reports coverage counts with their scope in LOG.

## Amendment — split (owner-signed 2026-10-03)

The first version asked for duplicates "from the folded map, across machines". Nothing collects
that: S17's sweeps name no file (no named folders exist), and the map's wire carries counts, not
per-file hashes. The owner chose to split: this contract keeps what the ledger already holds; S18
lets the owner name folders; S19 finds duplicates across machines. Budget 500 to 300.
