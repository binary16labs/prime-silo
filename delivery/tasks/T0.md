# T0 — Prove the trainer: ROCm-on-Windows + eGPU + a real QLoRA step

## Goal

Prove the RX 9060 XT (RDNA4/gfx1200) in the Razer Core X eGPU can run a real QLoRA step under
ROCm-on-Windows + Unsloth, before any data-pipeline investment. This is the make-or-break hardware
gate for all of EP-T. Everything downstream assumes this is _true_, not _hoped_.

## Context pointers (never inline content)

- Design plan: `~/.claude/plans/mellow-tinkering-swan.md` — "Phase 0", "Top risk", fallback ladder
- Hardware: T480 (i5-8th, 16GB RAM) + Razer Core X (TB3) + Sapphire Pulse RX 9060 XT 16GB
- Support: Unsloth AMD docs (unsloth.ai/docs/get-started/install/amd) — native-Windows ROCm + WSL2;
  RDNA4 wants ROCm 7.0.2+ (verified on the T480 at ROCm 7.13 / torch 2.11.0+rocm7.13.0); QLoRA 4-bit only (no from-scratch pretrain)
- Base for smoke: Qwen2.5-Coder-7B-Instruct (16GB → comfortable QLoRA at 7–8B)
- Fallback ladder if native-Windows ROCm won't enumerate the GPU: (1) WSL2 ROCm same install;
  (2) cloud ROCm/CUDA for training only, serve local; (3) smaller base. Windows stays host in all.

## TDD plan

1. `scripts/gates/t0.py` written first, red: asserts `rocm-smi`/`hipInfo` reports gfx1200 + ~16GB,
   and that a saved smoke-run artifact (adapter + final loss + step count) exists — fails cleanly
   with reason `gpu_absent` / `no_smoke_run` when the hardware/run isn't there.
2. Bring hardware up (owner: drivers + eGPU attach), re-run gate scenario 1 → gpu enumerates.
3. Run the 30-step QLoRA smoke (`scripts/train/smoke/`), gate scenario 2 → adapter + loss curve saved.

## Acceptance (BDD)

```gherkin
Feature: the QLoRA trainer is proven on real RDNA4 eGPU hardware
  Scenario: the eGPU enumerates for compute
    Given the Razer Core X + RX 9060 XT attached to the T480 over Thunderbolt-3
    And ROCm-on-Windows (or the WSL2 fallback) installed
    When the gate probes the compute device
    Then rocm-smi / hipInfo reports gfx1200 with ~16GB VRAM

  Scenario: a real QLoRA step completes and saves
    Given Unsloth installed on the enumerated device
    When a ~30-step 4-bit QLoRA runs on Qwen2.5-Coder-7B over a toy dataset
    Then training loss is recorded for every step and decreases overall
    And a LoRA adapter is written to disk and reloads without error

  Scenario: honest failure when the GPU is unavailable
    Given no compute device reports gfx1200
    When the gate runs
    Then it exits non-zero with reason gpu_absent and marks nothing as passed
```
