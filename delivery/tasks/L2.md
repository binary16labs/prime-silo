# L2 — Inbound poison gate (integrity boundary at admission)

## Goal
The leak gate is outbound privacy only. Staged raw arriving from many machines must pass an inbound
integrity/validation gate — a trust boundary symmetric to the leak gate — before synthesis or training,
so a corrupted or injected session on one machine cannot flow into the corpus. Extends R17/R20/R31.

## Context pointers (never inline content)
- Design: architecture/SOLUTION-longview-self-learning.md §4.2 (R40 poison gate)
- Symmetry reference: scripts/longview/lib/leak_gate.mjs (outbound term/sid scan) — this is its inbound twin
- Runs at admission, before a session_staged event is emitted as admissible; rejection is ledgered
- Requirement R40

## TDD plan
1. Hash-integrity test red: content not matching its declared content_hash is rejected.
2. Shape test: malformed/oversized/structurally-invalid session rejected with a reason.
3. Injection test: a blob carrying a forged KEL control record is rejected as non-data.
4. Pass-through test: a well-formed genuine session passes and is marked admissible.

## Acceptance (BDD — every Scenario must map to an automated test)
```gherkin
Feature: an inbound integrity boundary symmetric to the outbound leak gate
  Scenario: a hash-mismatched blob is refused admission
    Given a staged session whose content does not hash to its declared content_hash
    When the poison gate runs at admission
    Then the session is rejected and never marked admissible to synthesis
  Scenario: an injected control record cannot pose as data
    Given a staged blob carrying a forged KEL control event
    When the poison gate runs
    Then it is rejected as non-data and the rejection is ledgered with a reason
  Scenario: a genuine session passes
    Given a well-formed session whose content matches its hash
    When the poison gate runs
    Then it is marked admissible
```

## Out of scope
Outbound leak/privacy (unchanged), backup (L3), synthesis logic. Inbound admission integrity only.

## Handoff
Verifier re-runs `node scripts/gates/l2.mjs` including the NEGATIVE cases (mismatch, injection) and
confirms they go RED when the gate is bypassed. Rejection reasons are enumerated in the gate output.
