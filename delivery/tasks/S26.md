# S26 — Drives: walk the estate from the catalogue, not the disk

**Signed by the owner 2026-10-25 as written.** Band L, 800 lines, declared up front.

## Goal

F: holds 1.1 million files and 237,508 duplicate sets. A list of duplicates cannot be acted on —
nobody makes 237,508 judgements. Standing **inside a folder** and seeing how much of it exists
elsewhere is a judgement, and it is the one that retires a tree.

A navigable view of each catalogued drive, built entirely from S21's catalogue. It reads no files
and needs no drive attached, and it moves nothing: it makes the decision possible, not taken.

## Design (the Scenarios are normative)

1. **A folder rollup, written once per pass by the worker that already exists.** Beside the summary
   and the duplicates list, the worker writes one row per folder: files, bytes, and the two figures
   that matter — how many of its files have another copy **outside that folder's subtree**, and how
   many bytes that is.
2. **Every surface here is bounded before it runs, and the bound is measured.** The rollup is on
   the worker. The two routes stay on the request thread, so each must be provably cheap rather than
   merely indexed: both use an index range over the path primary key rather than `substr()`, neither
   may read more rows than the folder it was asked about, `/library/folder` pages at a cap that
   lives with the query, and
   `/library/neighbours` refuses outright above a file count it reads from the rollup before doing
   any work. An index fixes a query; only a bound fixes a placement. S21's D3 is this epic's lesson
   and this contract failed it twice — the measurements are in the log, not here.

3. **"Duplicated elsewhere" is defined precisely**, being the number the owner acts on: a file
   counts when its sha256 also appears outside the folder's subtree. Copies _within_ it are counted
   separately — a folder duplicated inside itself is a different problem from one duplicated
   against another tree.
4. **Two navigation routes, and both are routes.** `GET /api/estate/library/folder?root=&path=&
offset=&limit=` returns the folder's immediate children — subfolders with their rollup, files
   with size, date and kind — plus the breadcrumb. `GET /api/estate/library/neighbours?root=&path=`
   names the folders holding the other copies of that folder's content, computed on demand because
   storing it per folder is what took 45 minutes. Both run under the same two guards and through
   the same shaper as every other question, and the privacy judgement is **symmetric**: the near
   side of a comparison is judged exactly as the far side is, because naming where a private file's
   bytes also live identifies that file's content. The contract said "one route" while the work
   shipped two, which is how the second one came to be neither measured nor guarded.
5. **The panel shows where the weight is.** Each row carries its size and duplicated-elsewhere
   share, so the cost is visible where the owner is standing, and the folders holding the other
   copies are named.
6. **The catalogue is the only source.** No route here opens a file or lists a directory. With the
   drive detached every figure is identical, because nothing came from the drive.
7. **Private paths are counted, never named** — the same judgement, in the same place, including the
   folder names themselves.

## Acceptance

```gherkin
Feature: the estate is walkable from its catalogue
  Scenario: a folder says how much of it exists somewhere else
    Given a tree catalogued whose files also exist under another tree
    When the owner opens that folder
    Then it reports how many of its files and bytes have a copy outside it
    And it names the folders those copies are in

  Scenario: copies inside a folder are not counted as copies outside it
    Given a folder holding two copies of one file and nothing else
    When the owner opens it
    Then its duplicated-elsewhere figure is zero
    And its duplicated-within figure is one file

  Scenario: the drive need not be there
    Given a catalogued drive that is not attached
    And a rollup built for that catalogue's own pass under the hub's own privacy policy
    When the owner walks it
    Then every folder, count and size is answered from the catalogue
    And no file or directory on any drive is read
    And the answer says it was resolved by the recorded name rather than by identity

  Scenario: a detached drive whose figures no longer match is refused, not dated as current
    Given a catalogued drive that is not attached
    And a rollup built before a later pass, or under a different privacy policy
    When the owner walks it
    Then it is refused with the reason
    And no stale figure is answered wearing a current date

  Scenario: a folder too big to compare without blocking is refused, not attempted
    Given a folder holding more files than the measured cap
    When the owner asks where the other copies are
    Then it is refused, naming the count and the cap
    And no partial list of folders is answered

  Scenario: a private file is counted and never named
    Given a folder holding one public and one quarantined file
    When the owner opens it
    Then the public file is named and the quarantined one is not
    And the folder's counts include both

  Scenario: the rollup is never worked out on the hub's thread
    Given a catalogue the size of the real F:
    When the rollup is being written
    Then the hub answers every request throughout, breathing repeatedly rather than once
    And the panel says the rollup is still being worked out

  Scenario: no route here reads more rows than the folder it was asked about
    Given a catalogue of any size
    When either navigation route answers about a named folder
    Then its query plan searches the path index rather than scanning the table
    And at the drive root it reads the root's own partial index, not every row on the drive
```

## Closing figure — 1,104 at the first hand-off; the figure after each round is in the log

The band stays **L, 800**: that is what was declared up front, and editing a declaration to match
its outcome is what made S22's figure wrong twice. The work measured **1,104 non-test lines**, over
band L and over the XL ceiling.

Not split. Splitting after the work is done buys nothing — a verifier reads the same 1,104 lines
under two headings while the board gains two entries and a second gate. Third under-estimate in a
row; the agreed fix is to measure as the work goes rather than predict once. Reasoning in full in
`board/LOG.md`.

## Out of scope

Moving, copying, zipping or deleting anything (EP-U U7–U10, human-signed). Marking a copy to keep —
worth doing, and it needs its own contract because it writes the owner's decisions. Browsing drives
that have no catalogue. Thumbnails or previews: the catalogue holds no content.

## Handoff

Nothing for the owner until it is signed. The first pass of the rollup runs on the next catalogue
pass, or once immediately for a drive already catalogued.
