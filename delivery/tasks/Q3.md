# Q3 — SRE: release honesty + operational health

## Goal

No release ships unbooted: the release workflow unpacks each artifact and runs the existing
desktop:localtest boot check (v1.2.8 becomes structurally impossible). One `/healthz` per process
(server, runtime) feeds the C2 top bar and doctor. Structured JSON logs with run_id/node_id
correlation; wedge events counted in the activity store. RUNBOOK-release.md codifies the
hard-won rules.

## Context pointers

- Plan §9 Q3 card (PLAN-local-power-unified-ui.md:468-475)
- Runbook contents: tag/commit ordering (v1.2.4 lesson), build guard (v1.2.9), rollback = delete release + refit as next patch, never reuse a tag
- Q3 must land before any release ships from this plan (§12 note)

## TDD plan

1. Red: deliberately broken artifact (missing runtime asset) fails the release smoke.
2. Red: /healthz degrades honestly (component-level) when lemonade is stopped.
3. Implement smoke + health + logs — green. 4. Runbook dry-run by a fresh agent session using only the doc.

## Acceptance

```gherkin
Feature: releases that boot, health that tells the truth
  Scenario: broken artifacts cannot publish
    Given a release artifact missing its runtime asset
    When the release smoke runs
    Then the workflow fails before publish naming the artifact

  Scenario: health is honest per component
    Given lemonade is stopped
    Then /healthz reports that component down while the process stays up

  Scenario: the runbook stands alone
    When a fresh agent session executes a release dry-run using only RUNBOOK-release.md
    Then it completes every step without consulting other sources
```
