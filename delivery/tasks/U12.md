# U12 — Check and Compare never open a file that is only in the cloud

**Directed by the owner 2026-11-15** ("Fix leak"), closing the leak claude-u1-verifier found at U1
round 2 (non-blocking findings 1 and 2, LOG 536fb432). Band S, 300 lines.

## Goal

No route reads a file OneDrive keeps only in the cloud. Opening one downloads it, and the T480's
OneDrive holds 793,659 of them. U1 guarded the catalogue pass. Two doors stayed open:

1. **Check of a folder that holds OneDrive.** `POST /library/check` with the profile folder walks
   into OneDrive and hashes any file whose size matches the catalogue. This predates U1, and Benny's
   `library_check` tool reaches it.
2. **Compare from or to a drive that holds a OneDrive root.** It is walked and hashed. Not reachable
   on the T480, whose OneDrive is on C:.

## Design

1. **The route refuses (400)** a Check path or a Compare side that is inside an offered OneDrive
   root **or holds one**. Fast and clear, for the folders the registry knows.
2. **The reader guards itself**, for the folders it does not know about. Before anything is read,
   `checkPaths` asks Windows (U1's `windowsCloudOnly`: attributes only, never opens a file) about
   each path it was asked about. A cloud-only file is answered `online-only` and never opened. A file
   in a folder the probe could not read is `unreadable` and not opened. If the probe fails, the
   check refuses and reads nothing. Paths are matched by their real long spelling (8.3 and junction
   safe, as U1 round 2).

Known and stated, not closed: a file that goes cloud-only between the probe and the read (U1's
TOCTOU).
