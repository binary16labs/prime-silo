# S17 — the map gets a producer

## Goal

The owner presses Sweep in the Estate Map panel and sees their own machine in it, without running a
script. Collectors (S1), the sweep (S0), the wire and its guard (S3) and the panel (S4) all exist;
nothing in the product connects them.

## Context pointers (never inline content)

- `delivery/board/LOG.md` — the 2026-10-03 entries
- `server/coordination/lib/estate_register.mjs` — `register()`, the one way into `state.maps`
- `scripts/estate_satellite_agent.mjs` — `latestMapPush()`, the heartbeat
- `server/coordination/lib/estate_map_fold.mjs` — the stale rule

## What is wrong now

1. **Nothing produces a map.** Across every tracked .js/.mjs, `runSweep` is called only by the bench
   and tests; nothing launches the satellite agent; no `estate-map-*.db` exists under BENNY_HOME. The
   panel has said "No node has pushed a map yet" since S4 shipped.
2. **"Stale" means the wrong thing.** The fold calls a machine stale when its SWEEP finished over 30
   minutes ago, while the panel says the node "has gone quiet" and the constant was chosen as "six
   missed pushes" — but the heartbeat re-sends the same sweep. A node pushing faithfully reads stale
   30 minutes after it swept; with a walker sweep of F: longer than that, the owner's own hub would
   read "gone quiet" the moment its first map lands.

## TDD plan

1. Factor map acceptance out of `register()` — policy refusal, allowlist, machine match — so the
   register route and the local producer go through ONE function. No second way into `state.maps`.
2. `estate_map_producer.mjs`: the node's map db path, its latest finished sweep as a push (moved from
   the agent, so hub and agent read it one way), and a single-flight sweeper with honest status.
3. GET/POST `/api/estate/sweep`. POST is loopback-only, takes volumes from the drive roots the hub
   detects plus any roots the owner configures, and answers 409 while a sweep runs. On boot the hub
   folds its own latest sweep from disk, through the same acceptance.
4. Record when the hub last HEARD from a machine and key stale on that; report sweep age beside it,
   never as staleness. A re-push of a sweep already held updates when it was heard, not a new copy.
5. Panel: the drives, a Sweep control, the running sweep's volumes and start, the last sweep's age.
   The manifest's "no button that changes anything" is reworded to what the button does.
6. Agent: `--sweep` runs a sweep before the first push, so a satellite produces too.

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: the map has a producer
  Scenario: the owner's first map is a click
    Given a hub with a quarantine policy and no map
    When Sweep is pressed for one volume and the sweep finishes
    Then the map holds that machine, from a push that went through the satellites' acceptance

  Scenario: no policy, no map — even from the hub itself
    Given no quarantine policy
    When a local sweep finishes
    Then nothing is folded and the panel says why

  Scenario: a heartbeat keeps a node live
    Given a sweep that finished 3 hours ago, pushed again 2 minutes ago
    When the map is folded
    Then the node is not stale, and its sweep age reads 3 hours

  Scenario: the hub stays responsive and single-flight
    Given a sweep is running
    When the map is read and Sweep is pressed again
    Then the map answers, and the second sweep is refused with the first one's start time

  Scenario: a LAN caller cannot start a sweep
    When a sweep is requested from a non-loopback address
    Then it is refused and nothing runs
```

## Out of scope

Scheduled sweeps; MFT adapters (only the walker is installed on the hub); the quarantine policy and
the register key (the owner's acts); apps and media collectors (S2, S14).

## Handoff

Verifier boots the hub with a throwaway policy in a temp coordination dir, presses Sweep in the real
panel against a small configured root, and confirms the machine appears. Then kills each guard —
acceptance bypassed, loopback check removed, stale keyed back on sweep age — and confirms the gate
goes red. The gate turns only knobs production turns (S13's rule): a small root is configured the
way an owner would configure one.
