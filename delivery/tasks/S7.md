# S7 — the governed executor: a signed move, verified before anything is removed

## Goal

The Prime-Silo node that owns the bytes executes a signed centralisation proposal: restartable copy to the
destination, destination hash verified against the source, `artifact_placed` at the destination, and only then
`artifact_evicted` at the source. The NAS catalog records the arrival directly, so client receipts are no longer
needed. **Human-signed** because it moves data.

## Context pointers (never inline content)

- `architecture/SOLUTION-estate-map.md` §4.3, §7 (nothing moves unsigned)
- `server/coordination/lib/estate_govern.mjs` (signed proposal + idempotent apply pattern, N5)
- `server/coordination/lib/nas_catalog.mjs` (arrival recording), `estate/nas-client.ps1` (the copy order it replaces)
- `packaging/desktop/updater_download.js` (retry, stall and truncation handling to mirror)

## TDD plan

1. No signature, a declined proposal, or a proposal signed for a different content set: nothing is written, exit non-zero.
2. Copy is restartable; an interrupted copy resumes and the result is verified by full hash.
3. Destination hash mismatch: the destination copy is quarantined, the source is untouched, the failure is an event.
4. Re-applying a completed proposal is a no-op (idempotent).

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: governed storage moves
  Scenario: an unsigned proposal moves nothing
    Given a raised but unsigned proposal
    When the executor is invoked for it
    Then no file is copied or removed and the executor exits non-zero

  Scenario: the source survives a bad copy
    Given a signed move whose destination bytes are corrupted in transit
    When the executor verifies the destination
    Then the source is not evicted and a failed verification event is recorded

  Scenario: a completed move re-applied does nothing
    Given a signed proposal that already completed
    When the executor runs it again
    Then no copy, placement or eviction is repeated
```

## Out of scope

Deleting duplicates without a destination copy; moves across machines that are not both online and registered.

## Handoff

Verifier runs the gate, then with owner signature centralises one real models folder from optimus to the NAS and
records bytes, time and the verification events in LOG.
