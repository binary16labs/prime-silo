# N6 — next-cycle flywheel planner (`estate_plan.mjs`)

## Goal
Close the loop to planning: from the N4 drift (pending + approved), project the **next flywheel turn** so the
owner knows what's coming before it runs — `+N clean sessions → ~M cards (minus the thin rate) → ~K Stream-A
rows → does the dataset drift cross its rebuild threshold → recommended action (map | rebuild | train)`.
Read-only over the drift + the dataset manifest + the eval report; the same projection renders on the cockpit
and feeds the :8788 flywheel's feedback banner, so both surfaces agree. Advances KR1.5 by giving the flywheel
a *planned* intake instead of a discovered one.

## Context pointers (never inline content)
- Plan: `architecture/SOLUTION-estate.md` §8.3 (planner), §10.
- Inputs: `estate_drift.mjs` (N4 delta); `scripts/train/dataset/manifest.json` (rows, cards_used, streams);
  `docs/train/T3-eval-report.md` (the A/B gap that says which stream is starved).
- Shared shape: the `flywheel` block already emitted by the LONGVIEW dashboard collector
  (`scratch/longview_run/dashboard/collect.mjs`) — the planner's projection must be renderable there too.
- Thin rate: `status.json` `map_thin` / backlog gives the historical thin fraction.

## TDD plan
1. Failing test: `planNextCycle` projects clean sessions → cards using the injected thin rate → implement.
2. Failing test: projected new Stream-A rows and the "crosses rebuild threshold?" boolean from cards-vs-manifest.
3. Failing test: recommended action is `rebuild` when new-cards-since-build ≥ threshold, else `map`, else `train` when drift empty and dataset fresh.
4. Failing test: pure/read-only — given fixtures it returns the projection and mutates nothing.
