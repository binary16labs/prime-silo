## Goal

From U6's answer ("what is only outside F:", per source), the owner gets **copy proposals they can
read, change and approve**: per source, how many files and GB would be copied, to which folder on F:,
whether F: has room, and what is left out and why. No byte moves in U7. U8 executes an approved
proposal.

## Design

1. **Storage policy** (`coordination/estate/storage-policy.json`, owner-edited from the Library tab;
   each edit is logged): `target` (F:), `layout` (`F:\consolidated\<source>\<original path>`),
   `never` (sources or folders never proposed), `exclude` (folder names never copied, e.g.
   `node_modules`, `.venv`, `__pycache__`, `$RECYCLE.BIN`, until S32's scopes exist).
2. **The planner is pure**: U6's per-source sole content + the policy + F:'s free space → one
   proposal per source: files, unique bytes, repeat bytes, excluded (files, bytes, by rule),
   cannot-tell (cloud-only: never proposed, counted), the target folder, and **fits / does not fit**
   with the margin. Content F: already holds is never proposed, and a source's repeats are proposed
   once (the others are listed as pointers to the one copy).
3. **Never-overwrite is planned, not hoped for**: a target path that already exists on F: with other
   content is a planned rename (`name (from <source>).ext`), shown before approval.
4. **Approval is the owner's**: a proposal is approved in the Library tab by the owner. The
   approval is recorded in the ledger with the proposal's digest (files, bytes, paths list hash) so
   U8 executes exactly what was approved and refuses anything else. An agent never approves.
5. **Stale proposals die**: a proposal is current only for the catalogue passes and policy it was
   made from (`rollupKeyFor`, as U6); a newer pass on the source or F: invalidates the approval.

## TDD plan
