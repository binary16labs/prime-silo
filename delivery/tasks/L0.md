# L0 — Knowledge event log (KEL): the truth substrate

## Goal
The knowledge event log is the single source of truth; Neo4j/Chroma/memo-ray/cards are rebuildable
projections. This task delivers its envelope schema, chain-hash + fold-to-state library, and a
versioned up-converter registry — reusing the B0 ledger mechanics verbatim, not a new persistence model.
Unblocks all of EP-L. Extends KR2.2 (one honest stream) to knowledge truth.

## Context pointers (never inline content)
- Design: architecture/SOLUTION-longview-self-learning.md §4.1 (envelope), §5.1 (schema), §5.6 (HLC/version/confidence)
- Reuse: server/coordination/lib/ledger.mjs (prev = sha256(prev raw line)[0..16], fold(events)→state, wx lock)
- Non-blocking write posture: architecture/SPEC-run-events.md ("failures here never propagate")
- Steers 1/7/8/10 in REQUIREMENTS §6.1; requirements R1–R7, R11, R32

## TDD plan
1. Schema tests red: every event type validates; missing required field rejected; unknown field rejected.
2. Chain test: edited historical line → validator reports 1-based line number (successor hash breaks).
3. Fold tests: valid_time≤T and txn_time≤T predicates answer "what was true / what did we know at T";
   a supersede event yields new version, prior raw line unchanged.
4. Converter test: an event at schema_version 1.0.0 with a 1.0.0→1.1.0 up-converter replays without error.

## Acceptance (BDD — every Scenario must map to an automated test)
```gherkin
Feature: the knowledge event log is truth; stores are projections
  Scenario: a correction never mutates history
    Given a card_asserted event E1 at txn_time T1
    When a card_asserted event E2 supersedes E1 at txn_time T2
    Then folding at txn_time T1 still yields E1, folding now yields E2, and E1's raw line is unchanged
  Scenario: the chain betrays an edited historical line
    Given a KEL with N appended events
    When any historical line is edited
    Then the validator reports the 1-based line number whose prev-hash no longer matches
  Scenario: bi-temporal queries are answerable
    Given events with distinct valid_time and txn_time
    When folded with a valid_time<=T predicate and separately a txn_time<=T predicate
    Then each returns the correct historical state for that axis
  Scenario: an out-of-version record still replays
    Given an event at schema_version 1.0.0 and a converter 1.0.0->1.1.0
    When the projector folds the log
    Then the event is up-converted and projected without error
  Scenario: a write failure never raises
    Given a KEL file that cannot be written
    When an append is attempted
    Then it degrades to a logged no-op and the caller is unaffected
```
