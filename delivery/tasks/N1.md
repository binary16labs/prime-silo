# N1 — estate probes: topology, drift, metrics

## Goal
Deterministic **probe functions** that turn raw inputs into the estate model's live view: machine
reachability + roles (hub/satellite topology), per-drive **drift verdict** (INTACT / DRIFT / CORRUPT) from
fingerprint manifests, eGPU + host metrics (VRAM, CPU-time liveness — never a tqdm line), and per-machine
session stats. Pure functions over **injected** probe inputs so they test without live hardware or the
network. Traces O2.KR2.2 (physical-estate telemetry).

## Context pointers (never inline content)
- Plan source: `architecture/SOLUTION-estate.md` §3.3.
- Consumes the N0 estate model (`server/coordination/lib/estate.mjs`); does not modify it.
- Drift semantics mirror the F:/D: verify tool: INTACT (snapshot==manifest) · DRIFT (source moved on) ·
  CORRUPT (snapshot != its manifest). Liveness lesson: prove by CPU-time/artifacts, not the log line.

## TDD plan
1. `driveDrift(manifest, live)` → INTACT when equal, DRIFT when the live fingerprint moved, CORRUPT when the
   snapshot bytes no longer match the manifest. Write first, watch fail.
2. `topology(machines)` → marks exactly one hub, the rest satellites, each with reachable/unreachable from an
   injected reachability map (no real network).
3. `liveness(sample1, sample2)` → alive only when CPU-time advanced between samples; a fresh log mtime alone
   does NOT rescue a wedge (the eGPU-wedge lesson).
4. `sessionStats(estate)` → per-machine counts with the quarantine flag excluded from the "usable" count.
5. Mutation: make `driveDrift` always return INTACT → gate RED; revert → GREEN.

## Acceptance (BDD — every Scenario must map to an automated test)
```gherkin
Feature: estate probes
  Scenario: drive drift verdict
    Given a drive snapshot and a live fingerprint that has moved on
    When driveDrift is computed
    Then the verdict is DRIFT, and CORRUPT when the snapshot no longer matches its own manifest

  Scenario: hub and satellite topology
    Given a machine registry with one trainer and one pulled-over-SMB laptop
    When topology is computed from an injected reachability map
    Then exactly one node is the hub and the other is a satellite with its reachability state

  Scenario: liveness by resource not log
    Given two probe samples where CPU-time did not advance but the log mtime is fresh
    When liveness is computed
    Then the job reads as stalled, not alive

  Scenario: per-machine session stats exclude quarantine
    Given an estate model with quarantined sessions flagged
    When sessionStats is computed
    Then quarantined sessions are excluded from each machine's usable count
```

## Out of scope

DONE updates BOARD + LOG; unblocks N2.
