# S23 — Everything lists the drive, fingerprints only where a question needs them, and the catalogue keeps itself current

## Goal

Three changes to the catalogue S21 builds:

1. **It is listed by Everything** (the MFT-reading tool the owner chose for speed) in seconds,
   instead of walked folder by folder. The walk stays as the fallback.
2. **It fingerprints only what a question needs.** S21 reads every byte of every file. S23 reads a
   file only if it could be a duplicate, or if a comparison asks about it, and keeps every
   fingerprint it makes. The rules for what is worth fingerprinting at all are explicit: rebuildable
   tool folders, tiny files, system junk and online-only cloud files are catalogued but not read.
3. **It keeps itself current.** The hub rescans attached, catalogued drives on an interval the
   owner sets in Prime-Silo's own config.

The catalogue becomes usable for finding files and seeing space within a minute of pressing
Catalogue, rather than after a night. The first full pass should take about 2 hours instead of 8,
and a rescan of an unchanged drive about a minute instead of 705 seconds. All of that is to be
measured (criteria below). Report only: nothing is moved.

## Why (measured on the real F:, 2026-10-11)

From Everything's index alone (13 s, no file contents read):

- F: holds 1,117,018 files, 1,550 GB. S21's full fingerprint of every byte took 7 h 55 m (round-1
  verifier). Reading 1.55 TB at the drive's ~55 MB/s is about 7.8 h on its own.
- **104,854 files (66% of the bytes, 1,029 GB) have a size no other file on F: has.** Identical
  files always have the same size, so these can never be duplicates on F: and never need reading to
  find duplicates.
- Of the 1,005,751 files that do share a size, 616,412 sit in rebuildable tool folders
  (node_modules, .git, venvs, caches; 8 GB in all), 251,781 are under 4 KB (0.3 GB) and 132 are
  system junk. **That leaves 137,426 files (513 GB) of the owner's content to fingerprint,** mostly
  photos (82,687 / 375 GB) and video (919 / 120 GB). Per-file disk seeks were most of the 8 hours;
  cutting a million files to 137k is where the time goes.
- **File extension is NOT a safe rule.** 6,749 of the 45,843 same-size groups of owner content mix
  extensions, and the same bytes are routinely `.jpg`/`.JPG`/`.jpeg`. Type is used to route and
  rank, never to rule a pair out (see S24 for type-specific review rules).
- An Everything listing of F: takes 4–13 s against S21's 705 s rescan walk. Everything's change
  journal keeps only about 30 minutes on the T480 (S1, `changesSince`), so it cannot drive a daily
  rescan; a full listing each time is fast enough.

## Changes to what S21 shipped (stated, because S21's contract promised otherwise)

1. **Not every file has a full fingerprint.** `sha256` becomes nullable. Rows gain `partial`
   (first and last 4 MB plus size), `level` (0 listed, 1 partial, 2 full) and `scope` (owner,
   rebuildable, tiny, junk, online-only). A catalogue built by S21 (every row fully fingerprinted)
   migrates as is: every row is level 2, and scope is computed from its path.
2. **S21's "a backup drive is compared without reading F:" becomes "F: is read only for
   fingerprints it does not hold yet, at most once per file, ever".** A backup file whose size
   matches an F: file with no fingerprint makes S23 read that F: file once and keep the result.
   A second comparison of the same drive reads nothing on F:.
3. **Per-file history events only for files with a full fingerprint.** The KEL's artifact events
   are keyed by hash. Changes to files without one are counted in the batch summary event.

## Design

### Part 1 — listing (Everything first, the walk as fallback)

1. **One pass, two possible listings.** Level 0 takes its list from Everything when
   `everythingAdapter().available(root)` says Everything indexes the drive, otherwise from S21's
   folder-order walk. Either way it records path, size, mtime, kind and scope for every file, and
   the catalogue is usable for finding files, kinds and space as soon as level 0 commits.
2. **Both sources apply the same exclusions** (S21's top-level skips, the estate store, and
   `isExcluded`'s OS internals). A test catalogues one tree both ways and requires identical rows.
3. **A listing that may be incomplete never removes a row.**
   - An Everything failure (`ES_UNAVAILABLE`, `ES_FAILED`, `ES_INCOMPLETE`) falls back to the walk,
     and the reason is recorded.
   - A listing with fewer than 99% of the files the catalogue already holds also walks instead. An
     exclusion set in Everything's own options could otherwise hide a folder silently.
   - A full walk runs when the last one is older than `ESTATE_LIBRARY_WALK_DAYS` (default 7).
   - S21's drive-identity guard and run-id removal rule are unchanged.
4. **Attributes from Everything.** `estate_map_files.mjs` passes Everything's file attributes
   through on each row. This change is additive only; nothing else in S1 changes, and the S1 gate
   stays green. A file marked online-only (the cloud recall attributes) is scope `online-only` and
   is never read, because reading it would download it. On the walk fallback, files under a folder
   whose reparse tag is a cloud tag (S1's `isCloudTag`) are treated the same way.

### Part 2 — levels: fingerprint only what a question needs

5. **Scope rules decide what is worth reading at all.**
   - `rebuildable`: inside a tool folder from a documented default list (node_modules, .git,
     site-packages, venvs, \_\_pycache\_\_, package caches). These are catalogued, never fingerprinted
     unless a comparison asks, kept out of the duplicates report (counted there as "rebuildable
     copies: N files, X GB"), and never consolidation targets.
   - `tiny`: under 4 KB. Kept out of the duplicates report; fingerprinted on demand.
   - `junk`: Thumbs.db, desktop.ini, .DS_Store, `._*`. Catalogued and flagged.
   - `online-only`: as point 4.
   - `owner`: everything else.
6. **Level 1, a partial fingerprint,** for owner files whose size another owner file on the same
   drive shares. Files up to 8 MB are read whole, so their partial fingerprint is their full one.
7. **Level 2, a full fingerprint,** for files whose partial fingerprint matches another's.
8. **Disk order.** Each level reads its files in listing order, which is folder order, so the head
   moves forward through the drive rather than seeking back and forth.
9. **Duplicates stay exact.** A duplicate is a full-fingerprint match, exactly as in S21. A
   unique-size file cannot have an identical twin, so leaving it unread loses no duplicate.
10. **On demand, and kept.** A comparison or an S22 check that needs a fingerprint the catalogue
    lacks computes the level it needs (partial, then full only on a partial match), writes it into
    the catalogue, and never computes it again unless the file's size or mtime changes.

### Part 3 — the schedule

11. **Config, the Prime-Silo way.** `ESTATE_LIBRARY_RESCAN_HOURS` (default 0 = off) and
    `ESTATE_LIBRARY_WALK_DAYS` (default 7) go in `commands/params.yaml`, are set with
    `node space set`, and are read as resolved runtime parameters.
12. **A job, not a scheduled task.** `server/jobs/library_rescan.js` extends `JobBase` with interval
    semantics (it checks every 15 minutes which drives are due), and `isEnabled()` is true only when
    the interval is above 0 and `ESTATE_STORE` is set. It runs on the primary under the runner's
    named lock.
13. **One librarian.** The job asks the hub's own single-flight librarian, passed through the runner
    context (a narrow addition to `job_runner.js`). A scheduled and a pressed pass can never run at
    once, and Stop stops either.
14. **Only drives that are there and already catalogued.** An attached drive whose last finished
    pass is older than the interval is due. A different drive at F: is never catalogued by the
    schedule. An unattached drive is skipped and logged, never counted as rescanned. A tick while a
    pass or comparison runs does nothing.
15. **Recorded and shown.** Each pass records `started_by` (owner or schedule), `listed_by`
    (everything or walk) and the reason for a walk. The Library line shows the listing source and
    time, how far the levels have got ("level 1: 41,200 of 137,426"), and when the next rescan is
    due, or "Rescans are off (ESTATE_LIBRARY_RESCAN_HOURS=0)".

## Pre-registered criteria (measured on the real T480 and F: by the verifier, reported either way)

- Level 0 of F: from Everything (listed, committed and usable for finding files) in **≤ 2 min**.
- A full first pass (levels 0–2) of F: in **≤ 3 h**, against 7 h 55 m for S21's full fingerprint.
  The author's estimate is about 2 h. If it misses, the report attributes the time.
- A rescan of unchanged F: from Everything in **≤ 90 s**, re-reading 0 of the owner's files.
- Duplicate sets among owner files equal those of a full-fingerprint catalogue of the same F:
  (the owner's S21 catalogue if one exists by then, otherwise a verifier's full pass).
- A real comparison run twice: the second run reads 0 bytes of F:.

## Owner questions (answer when signing)

1. **The rescan interval** on the T480 once merged. Recommendation: 24 hours
   (`node space set ESTATE_LIBRARY_RESCAN_HOURS=24`).
2. **Everything running at login.** It must run in your login session for the hub to use it. It
   has been set to start at login since 2026-09-13; confirm it stays. Otherwise rescans use the
   slower walk, and the panel says so.
3. **Integrity checking is left out.** Levels mean unique-size files carry no fingerprint, so silent
   corruption in them goes unnoticed. A background "fingerprint everything, slowly" option is
   possible later. Confirm it can wait.

## Out of scope

- Type-specific "possible duplicate" rules: photos, tag-free media fingerprints, folders, archives
  and versions (S24).
- Fingerprints crossing machines; the estate-wide content index and copy counts (the
  consolidation epic).
- Following Everything's change journal continuously; wall-clock scheduling.
- Moving, deleting or de-duplicating anything (S7).

## Handoff

One gate run and one independent check by a non-author verifier on the real T480 and F:. The
verifier:
- measures the five criteria;
- stops the Everything client to see the walk fallback and its reason;
- simulates an absent drive and a different drive at the same root;
- sets the interval via `node space set` in a test install, never the owner's `.env`.
