# P6 — The executor hook: where the zeros end

## Goal

Supply the real hook `P1`'s schema was shaped for. Drive a **subject** (a persona→model assignment,
design D2) through the SDLC manifest and fold the resulting G0 run-event stream into the eight
`SandboxResult` fields — deriving only what the stream actually supports, and reporting every other
field as `unmeasured` (R1, R2, R3, R6, R13).

Split from the original P1 on 2026-08-04 (owner decision). `P1` owns the schema; this owns the
measurement.

## Context pointers

- Design: `architecture/SOLUTION-model-plurality.md` §4.2 (the field→source table) and §4.1
- Event schema: `runtime/benny/pypes/events.py` — the G0 stream is the ONLY source (design D5)
- Reuse `model_resolver.resolve_model()`'s per-persona map; never add a second resolver

## Known constraint, established during the original P1

`pypes/orchestrator.py` emits `node_finished` with `duration_ms` and passes **no** `tokens_in`,
`tokens_out` or `model`, though the G0 schema in `events.py` already defines all three. Against the
orchestrator as it stands, a real run can therefore measure only `iteration_latency_ms_p95` and
`loop_count_p95`. **That is the correct output** — two real numbers and six honest `unmeasured` — and
the gate must assert it rather than paper over it. Populating those fields is a separate contract.

## TDD plan

1. Red: a stream with no token fields yields `None` for `total_tokens`, `context_efficiency` and
   `total_cost` — a mutation summing the reporting subset turns the gate RED.
2. Red: zero gate evaluations yields `None` for `constraint_adherence`, not `1.0`. (The old stub
   awarded a perfect adherence score to a run that never happened.)
3. Red: a subject label resolves through `resolve_model()`; an unknown label or unknown subject is
   refused rather than silently defaulted.

## Acceptance

```gherkin
Feature: the harness derives what the stream supports and admits the rest
  Scenario: partial token reporting is unmeasured, not a partial sum
    Given a run where one node reports no tokens
    When metrics are derived
    Then total_tokens is unmeasured rather than the sum of the rest

  Scenario: a heterogeneous subject resolves per persona
    Given a subject assigning different models to implementer and reviewer
    When the hook runs
    Then each persona resolves through resolve_model to its assigned model
```

## Out of scope

Changing the orchestrator to emit token fields (its own contract). The rubric that makes the two
tool metrics derivable (`P2`). Ledger and lineage emission (`P3`).
