# S0 — the estate map model: node index, collector interface, snapshot to CAS

## Goal

A node can hold its own map (volumes, files, apps, media) in a local SQLite index filled by pluggable
collectors, and publish a sweep as a CAS snapshot plus one `sweep_recorded` event. Every later S-task writes
into or reads from this model, so it fixes the schema and the privacy boundary once (KR2.2: the physical estate
joins the one event stream).

## TDD plan

1. `openMap` creates `volumes`, `files`, `apps`, `media`; reopening is idempotent.
2. A collector is `{ name, kind, collect(ctx) -> AsyncIterable<row> }`; `runSweep` records which collector
   produced each volume's rows, and a per-collector error without aborting the sweep.
3. Privacy: a path matching a quarantine rule is stored as `sha256(path)` + category, never the path.
4. `publishSweep` writes a CAS snapshot and a `sweep_recorded` event naming the snapshot hash, the scope walked
   and the collectors used.

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: estate map model
  Scenario: a sweep with a failing collector still publishes, and says which failed
    Given a files collector that yields rows and an apps collector that throws
    When runSweep and publishSweep run
    Then the snapshot holds the file rows and sweep_recorded lists apps as errored

  Scenario: quarantined paths never leave the node as paths
    Given a quarantine rule matching "cv"
    When a file C:/Users/x/Documents/cv-2026.docx is collected
    Then the index row and the snapshot hold its path hash and category but not the path

  Scenario: the scope travels with the result
    When a sweep of volume F: is published
    Then sweep_recorded.payload.scope lists F: and no other volume
```
