# S0 — the estate map model: node index, collector interface, snapshot to CAS

## Goal

A node holds its own map (volumes, files, apps, media) in a local SQLite index filled by pluggable collectors,
and publishes a sweep as a CAS snapshot plus one `sweep_recorded` event. It fixes the schema and the privacy
boundary once for every later S-task (KR2.2: the physical estate joins the one event stream).

**Amended 2026-09-13 (owner decision, after four verifier FAILs of pattern redaction; budget 450 -> 650):**
privacy is STRUCTURAL. Names are published only under `publicRoots` the owner lists (e.g. F:/nas, F:/media);
everything else is recorded as totals only. Quarantine rules narrow what is public; they never widen it.

## TDD plan

1. `openMap` creates `volumes`, `files`, `totals`, `apps`, `media`; idempotent. Collector:
   `{ name, kind, volumes?, collect(ctx) }`; one collector's error is a code, never text, and never aborts others.
2. Decide on what is stored: a path is canonicalised FIRST, then judged public (under a public root at a segment
   boundary, and matching no rule). Text fields (app name/version/publisher, media title) are judged as the exact
   strings that would be stored.
3. A non-public file leaves no per-file trace: no name, no path hash. It adds only to `totals` (volume,
   category, files, bytes). Non-public media and apps are counted, not listed. App identity (name, version,
   publisher) is public unless a rule matches it; its install location is public only under a public root.
4. Each successful collector run replaces its previous rows, so adding a rule or removing a root cleans the index.
5. `publishSweep` writes a CAS snapshot and a `sweep_recorded` event naming snapshot hash, scope and collectors.

## Acceptance (BDD — every Scenario must map to an automated test)

```gherkin
Feature: estate map model
  Scenario: a sweep with a failing collector still publishes, and says which failed
    Given a files collector that yields rows and an apps collector that throws
    When runSweep and publishSweep run
    Then the snapshot holds the file rows and sweep_recorded lists apps as errored with a code

  Scenario: outside a public root only totals are recorded
    Given public root F:/nas and a file C:/Users/x/Documents/cv-2026.docx
    When it is collected
    Then no index row, snapshot line or event holds its name or a hash of its path
    And the documents total for C: counts its file and bytes

  Scenario: a quarantine rule inside a public root is judged on the stored text
    Given public root F:/nas, rule "cv", and a file F:/nas/cv-2026/‥/notes.txt (a folder named U+2025)
    When it is collected
    Then it is counted only in totals, because its stored text still contains "cv-2026"
    And F:/nas/tmp/../notes.txt is listed as F:/nas/notes.txt

  Scenario: a later rule removes rows an earlier sweep published
    Given a sweep that listed F:/nas/cv.pdf and an app "CV Builder"
    When a sweep with rule "cv" succeeds
    Then neither appears in the index or the new snapshot

  Scenario: the scope travels with the result
    When a sweep of volume F: is published
    Then sweep_recorded.payload.scope lists F: and no other volume
```
