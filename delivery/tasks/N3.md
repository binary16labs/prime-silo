# N3 — drill-down cards + board & LONGVIEW tie-in

## Goal

Make the estate console the **one governance surface**: interactive drill-down cards (glance → drill →
explain-provenance, drill via the `lineage-timeline`), plus tie-ins that read the **delivery board** tasks
lane and the **LONGVIEW pipeline** into the same console. Every number derives from the estate log + the
board/ledger — no hidden state. Human-signed: this promotes the estate surface to the shared observability
plane. Traces O2.KR2.4 (verification/governance observability).

## Context pointers (never inline content)

- Plan source: `architecture/SOLUTION-estate.md` §3.4 (tie-ins), §5 (privacy invariant), §6.
- Extends N2's `estate.html` + `estate_api.mjs` (both exist post-N2). Board source: `delivery/board/BOARD.md`
  / `board/LOG.md`. LONGVIEW progress: `<ws>/longview/progress.json` (Dial fraction). Privacy: the estate
  model's quarantine flag — a quarantined session must never surface its content in a card.

## TDD plan

1. `estate_api.mjs` `/api/estate/board` folds BOARD.md into a lane summary (READY/CLAIMED/VERIFY/DONE counts
   - the topmost items). Write the test first, watch fail.
2. A drill-down card payload for a machine returns its provenance timeline events (for the lineage-timeline)
   AND omits any quarantined session's content (only the flag + count).
3. `/api/estate/longview` returns the pipeline stage fractions for the Dial from progress.json (or a null
   shape when absent — no fabricated progress).
4. Page: a card exposes a drill affordance whose target is the lineage-timeline element; gate asserts the
   wiring exists in source.
5. Mutation: make the card payload include a quarantined session's content → gate RED (privacy); revert → GREEN.
