# P0 — Roster schema + validator (subjects, tiers, frozen rubric)

## Goal

A benchmark subject is a **persona→model assignment plus serving topology**, not a model — so a
heterogeneous roster (E4B as reviewer, 12B as implementer) ranks as one unit and the incumbent is just
another subject. Rosters are declared in a manifest, so adding a model is an edit, not code
(R4–R8, R10).

## Context pointers

- Design: `architecture/SOLUTION-model-plurality.md` (requirement → component map §4.6)
- Requirements: `architecture/REQUIREMENTS-trained-model-workflows.md` (R numbers cited inline)
- Reuse `model_resolver.resolve_model()`'s existing per-persona map; never add a second resolver

## TDD plan

2. Red: a subject assigning the judge model is rejected (self-judging).
