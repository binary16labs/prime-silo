# L10 — flywheel-daemon (trigger + liveness)

## Goal
The loop orchestrator advances staged → synthesis → dataset → train → serve → agents → sessions,
triggered hybridly (fs-watch on D: staging reactively + a cron sweep backstop), every mutating turn
gated by the L7 single-winner claim. Full-hybrid liveness: artifact/CPU/mtime watchdog + external
supervisor heartbeat + dead-man clean abort (fail clean, never wedge the box). R22, R28, R29, R35.

## Context pointers (never inline content)
- Design: architecture/SOLUTION-longview-self-learning.md §4.5 (trigger/claim) + §4.6 (liveness); steers 5/11
- Reuse: L7 loop_claim.mjs (flywheel-turn wx lease), G0 runs/<id>/events.jsonl heartbeats for liveness
- Liveness lesson (NOT log lines): [[verify-gpu-job-liveness]] + house-trainer wedge protocol (CPU-time/mtime/artifacts)
- Requirements R22, R28, R29, R35

## TDD plan
1. Trigger test red: a new staged manifest fires a turn; the cron sweep also fires one; both take the L7 claim.
2. Single-winner test: two daemons on two machines → exactly one runs the turn (reuses L7).
3. Watchdog test: a wedged job (CPU-time flat, artifacts/mtime stale) is detected as stalled, not alive.
4. Dead-man test: on wedge the daemon aborts clean — stops the job, releases the lease, emits run_failed, alerts.

## Acceptance (BDD — every Scenario must map to an automated test)
```gherkin
Feature: the loop turns reactively and on a backstop, alive-checked, fail-clean
  Scenario: reactive and cron triggers both advance a turn
    Given a new staged manifest and, separately, a scheduled sweep
    When each fires
    Then a loop turn starts, each having taken the flywheel-turn claim
  Scenario: only one machine runs a turn
    Given two daemons racing on the claim
    When they trigger concurrently
    Then exactly one advances the turn
  Scenario: a wedged job is detected by resource, not by logs
    Given a job whose CPU-time is flat and artifacts/mtime are stale while its log looks quiet
    When the watchdog checks liveness
    Then it reports stalled, not alive
  Scenario: a wedge aborts clean
    Given a detected wedge
    When the dead-man switch fires
    Then the job is stopped, the lease released, run_failed emitted, and an alert raised — the box is not wedged
```

liveness only; the daemon calls existing stage skills, it does not reimplement them.
