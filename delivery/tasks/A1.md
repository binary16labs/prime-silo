# A1 — Windowing/assembly helper + semantic cache

## Goal

One reusable helper that splits work into windows sized for ≤~400-token outputs, runs each window
as a separate generation, assembles results losslessly in code, and validates each window against a
per-task schema with bounded retry (max 2) then honest partial failure. Includes the SQLite
semantic content-addressed cache (judge-verdict-gated hits, `cached: true` honesty).

## Context pointers

- Plan §2 A1 card (PLAN-local-power-unified-ui.md:142-147): prefill economics — maximize work per window
- Facts table rows 1-2 (≤400-token output budget; TTFT 22 s @ 7.7k input — fewer, fuller windows)
- LONGVIEW assembly pattern: scripts/longview/ (extract shared code into runtime/brain/, import from both)
- Cache key: hash(window text + system prompt + schema + model id + ctx + sampling params); per-home, size-budgeted

## TDD plan

1. Property test red: 50-item synthetic task → all 50 exactly once in assembled output.
2. Poisoned-window test red: garbage window → `partial` result naming the failed window.
3. Implement splitter/assembler/validator — green. 4. Cache tests: identical call hits (0 calls), any param change misses; hit carries `cached: true`.

## Acceptance

```gherkin
Feature: lossless windowed execution on a short-output local model
  Scenario: nothing is lost in assembly
    Given a 50-item synthetic task split into windows
    When all windows generate and results are assembled
    Then all 50 items appear exactly once in the output

  Scenario: a poisoned window fails honestly
    Given one window whose model output is garbage after 2 retries
    Then the run result is 'partial' with the failed window identified, never silent loss

  Scenario: cache hits are honest and cheap
    Given a window previously generated with a passing judge verdict
    When the identical window is requested again
    Then it returns with zero model calls and is flagged cached true
```
